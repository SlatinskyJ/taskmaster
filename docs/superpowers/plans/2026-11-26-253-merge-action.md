# Merge approved PRs with a GitHub Action: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Issue:** #253 Merge approved PRs with a GitHub Action.
**Goal:** The clean path of a merge-me run (update the PR with `main`, wait for CI, squash-merge, next PR) runs as a GitHub Action with no agent. The agent skill `merge-approved-prs` only runs for PRs the Action hands over.
**Architecture:** A workflow on the default branch runs one Node script per event. The script reads the labelled PRs over the GitHub API, decides with pure functions which single PR to act on, and does one step (update the branch, or turn on auto-merge, or hand the PR over with one comment). GitHub's own auto-merge does the merge when the required checks pass.
**Tech stack:** GitHub Actions, Node 22 (TS run directly, like `scripts/post-judge-review.ts`), Vitest, `fetch` to the REST and GraphQL APIs (no new npm dependency).
**Spec:** none (tooling). Rules it implements: skill `merge-approved-prs` sections 1 and 2; `CLAUDE.md` labels and Trivial PRs.
**Size:** about 300 changed lines (script about 200, workflow about 60, skill and CLAUDE.md edits about 40), plus tests. Touches CI, a protected area.

## Global constraints

- Only Jakub adds `merge-me`. The Action never adds a label; it only takes `merge-me` off after the merge.
- Squash merge only. Never bypass the ruleset, never force-push, never merge a PR whose required checks did not pass (GitHub auto-merge enforces this).
- The workflow never checks out or runs PR code: it checks out the default branch only, and runs on `pull_request_target`, `workflow_run`, `push` and `workflow_dispatch`, which all run default-branch code.
- Every third-party action is pinned to a full commit SHA with a `# vX` comment (Dependabot keeps them up to date).
- Token: a GitHub App token (`actions/create-github-app-token`, secrets `MERGE_APP_ID` and `MERGE_APP_PRIVATE_KEY`), because work done with `GITHUB_TOKEN` starts no workflows: CI would not run after an update, and `deploy prod` would not run after a merge. If Jakub picks a fine-grained PAT instead, only Task 3's token step changes (secret `MERGE_TOKEN`).
- English code, logs and comments. A PR comment from the Action ends with the footer `---\n_Posted by the merge-me Action_`.

## Review focus

1. A PR that gets new commits after the label: must be handed over, never merged. Test in Task 1.
2. `main` moves while a PR's CI is running: the PR is behind again, so the next run updates it again. Never two PRs updated at once (wasted CI, racing merges). Tests in Task 1.
3. An update-branch call that fails with a conflict (HTTP 422): hand the PR over once, move on to the next PR. Test in Task 2.
4. A run that fires twice for the same event: no duplicate comment (marker check) and no second update while CI is pending. Tests in Task 1 and Task 2.
5. A PR in a GitHub stack: handed over (the API refuses update and merge on stacked PRs). Test in Task 1.

### Task 1: Queue decisions (pure)

**Files:**
- Create: `scripts/merge-queue/decide.ts`
- Test: `tests/merge-queue-decide.test.ts`

**Interfaces:**
- Produces:
  ```ts
  type Ci = 'green' | 'pending' | 'red'
  type PrFacts = {
    number: number
    draft: boolean
    labelledAt: string            // ISO, latest `labeled` event for merge-me
    needsJakubAt: string | null   // ISO, latest `labeled` event for needs-jakub, if the label is on
    commitsAfterLabel: { subject: string; isMergeOfMain: boolean }[]
    ci: Ci                        // required checks on the head SHA
    unresolvedThreads: number
    inStack: boolean
    behind: boolean               // mergeable_state === 'behind'
    autoMergeOn: boolean
    handedOver: boolean           // a comment with the handoff marker exists after labelledAt
  }
  type Verdict = { ok: true } | { ok: false; reason: string }
  type Action =
    | { kind: 'update'; pr: number }
    | { kind: 'auto-merge'; pr: number }
    | { kind: 'hand-over'; pr: number; reason: string }
    | { kind: 'wait'; pr: number }
    | { kind: 'idle' }
  function entryCheck(pr: PrFacts): Verdict
  function nextActions(prs: PrFacts[]): Action[]
  ```

### Task 2: GitHub calls and the run

**Files:**
- Create: `scripts/merge-queue/github.ts` (REST + GraphQL over `fetch`, token from `GH_TOKEN`)
- Create: `scripts/merge-queue/run.ts` (entry point: `node scripts/merge-queue/run.ts`)
- Test: `tests/merge-queue-run.test.ts`

**Interfaces:**
- Consumes: `entryCheck`, `nextActions`, `PrFacts`, `Action` from Task 1.
- Produces:
  ```ts
  interface Gh {
    labelledPrs(): Promise<PrFacts[]>                  // open PRs with merge-me, facts filled in
    updateBranch(pr: number): Promise<'ok' | 'conflict'>  // PUT pulls/<n>/update-branch; 422 → 'conflict'
    enableAutoMerge(pr: number): Promise<void>         // GraphQL enablePullRequestAutoMerge, SQUASH
    comment(pr: number, body: string): Promise<void>
    removeLabel(pr: number, label: string): Promise<void>
    recentlyMerged(): Promise<number[]>                // merged PRs still carrying merge-me
  }
  function run(gh: Gh, log: (line: string) => void): Promise<void>
  const HANDOFF_MARKER = '<!-- merge-queue:handoff -->'
  ```
- `labelledPrs` facts: label times from `issues/<n>/events`; commits from `pulls/<n>/commits` (a merge of main = 2 parents and the second parent is on `main`); required checks from `commits/<sha>/check-runs` filtered to the ruleset's required names (read once from `rules/branches/main`); threads from GraphQL `reviewThreads(first:100){nodes{isResolved}}`; stack from `stacks?pull_request=<n>`; `behind` from `pulls/<n>` `mergeable_state`; `autoMergeOn` from `auto_merge != null`; `handedOver` from `issues/<n>/comments` containing `HANDOFF_MARKER` after `labelledAt`.

- [ ] **Step 1: Write the failing tests** in `tests/merge-queue-run.test.ts` with a fake `Gh` that records calls:
  - `run` takes `merge-me` off every PR from `recentlyMerged()` first.
  - an `update` action whose `updateBranch` returns `'conflict'` → one `comment` containing `HANDOFF_MARKER` and `'update with main has a conflict'`, and `run` then acts on the next passing PR.
  - a `hand-over` action → one comment: marker, the reason, and the line `Run skill merge-approved-prs for this PR.` plus the footer; the label stays (no `removeLabel` for it).
  - an `auto-merge` action → `enableAutoMerge(pr)` once, no comment.
  - `wait` and `idle` → no write call at all.
- [ ] **Step 2: Run** `pnpm vitest run tests/merge-queue-run.test.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** `run` in `run.ts` (the module's main block builds the real `Gh` from `github.ts` only when run directly) and `github.ts`. `github.ts` throws with the URL and status on any non-2xx except the 422 that `updateBranch` maps. No retry loops: the next event runs again.
- [ ] **Step 4: Run** both test files. Expected: PASS. Then `pnpm typecheck && pnpm lint`.
- [ ] **Step 5: Commit** `merge-queue: run one step per event against GitHub`.

### Task 3: Workflow

**Files:**
- Create: `.github/workflows/merge-queue.yml`

- [ ] **Step 1: Write the workflow:**
  - `on`: `pull_request_target: { types: [labeled] }`, `workflow_run: { workflows: [CI], types: [completed] }`, `push: { branches: [main] }`, `workflow_dispatch`.
  - `permissions: {}` at the top (the App token does the writes); job `if`: for `pull_request_target`, only when `github.event.label.name == 'merge-me'`.
  - `concurrency: { group: merge-queue, cancel-in-progress: false }`: one run at a time, later events queue.
  - Steps: `actions/create-github-app-token` (pinned SHA) with `app-id: ${{ secrets.MERGE_APP_ID }}`, `private-key: ${{ secrets.MERGE_APP_PRIVATE_KEY }}`; `actions/checkout` (same pinned SHA as `ci.yml`) with `ref: main` and `persist-credentials: false`; `actions/setup-node` (same pin) Node 22; `node scripts/merge-queue/run.ts` with `GH_TOKEN` from the App token step. No `pnpm install`: the script uses only Node built-ins.
  - `timeout-minutes: 5`.
- [ ] **Step 2: Check** `actionlint` (via `docker run --rm -v "$PWD":/repo -w /repo rhysd/actionlint:latest`), or if Docker is not available, `npx --yes actionlint@<pinned>`; expected: no output.
