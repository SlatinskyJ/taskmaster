# Multi-user viewer page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (CLAUDE.md PR flow). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/dev/multi` on dev and PR previews: a row of phone-size frames, each the real app logged in as a demo user, so Jakub can test a flow across users side by side.

**Architecture:** A framework-free layout module (`src/lib/multiLayout.ts`) owns the list of devices, sizes, defaults, local-storage parsing and each frame's `name`/`src`. The route `src/routes/dev/multi.tsx` renders the toolbar and one `DeviceFrame` per device; it logs each frame in through `frameLoginFn` (PR 1) and hands the token to the iframe as `name="tm-frame:<token>"` and `src="<path>?tmFrame=<token>"`. Frames are never refreshed by the page except by **Obnovit** / **Obnovit vše** (design: "three phones on a desk").

**Tech Stack:** TanStack Router file route, React, existing `Button`/`Select`/`Input` (`src/components/ui/`), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-26-multi-user-viewer-design.md` ("The page /dev/multi", Goals) + §6 "Multi-user viewer" bullet. Wireframe: https://claude.ai/artifact/XF1EyQr2t55bVbP3MfgDz6. Issue: #265 (this PR `Closes #265`). Stacked on PR #267 (branch `265-frame-login`).

## Global Constraints

- The page exists only where `getDevPagesAllowed()` is true; elsewhere `notFound()` (same `beforeLoad` as `src/routes/dev/ui.tsx`).
- The page never changes app behaviour inside a frame: no polling, no auto-reload, no `postMessage` into the app. Only Obnovit / Obnovit vše / changing the user / editing the address reload a frame.
- Users: `admin`, `tata`, `starsi`, `mladsi` (the demo family). The same user may be in several frames; each frame has its own session.
- Sizes (wireframe): `phone` 390×844 "Telefon", `small` 360×740 "Malý telefon", `tablet` 820×1180 "Tablet", tablet drawn at scale 0.7 (Jakub accepted 2026-11-26).
- Czech labels in `src/lib/strings.ts` under `cs.devMulti` (exact copy below). Toolbar button **Přidat zařízení** (Jakub, 2026-11-26, wireframe comment; replaces "Přidat telefon").
- Layout remembered per browser in `localStorage` key `tm.devMulti.v1`, every access in try/catch; an unreadable value falls back to the default.
- Token values per PR 1: `'-'` = no token (`NO_TOKEN`, `FRAME_NAME_PREFIX`, `FRAME_QUERY` from `src/lib/frame.ts`).

Copy (`cs.devMulti`): `title: 'Více uživatelů'`, `add: 'Přidat zařízení'`, `reloadAll: 'Obnovit vše'`, `reload: 'Obnovit'`, `remove: 'Odebrat'`, `user: 'Uživatel'`, `size: 'Velikost'`, `address: 'Adresa'`, `cancel: 'Zrušit'`, `confirmAdd: 'Přidat'`, `loggingIn: 'Přihlašuji…'`, `loginFailed: 'Přihlášení se nepovedlo.'`, `retry: 'Zkusit znovu'`, `empty: 'Žádné zařízení. Přidej první.'`, `inHand: 'v ruce'`, `remembered: 'Rozložení se pamatuje v tomto prohlížeči.'`, `sizes: { phone: 'Telefon', small: 'Malý telefon', tablet: 'Tablet' }`, `users: { admin: 'Admin', tata: 'Táta', starsi: 'Starší', mladsi: 'Mladší' }` (reuse an existing strings entry for these names if one exists).

## Review Focus

1. **Obnovit after the person logged out/in inside a frame** → the reload uses the frame's *current* token (read back from `iframe.contentWindow.name`), not the one the page stored. (Task 1 `tokenFromName`, Task 3 e2e.)
2. **Address field with junk** (`ukoly`, `https://evil.example/x`, `//evil`, `javascript:`) → only same-origin paths are accepted; others leave the address unchanged. (Task 1.)
3. **Stored layout from an older/broken version** (bad JSON, unknown user, unknown size, 0 devices) → default layout or the valid rest; never a crash. (Task 1.)
4. **`frameLoginFn` refuses or throws** (rate limit, `not_available`, network) → that frame shows `loginFailed` + `retry`; the other frames keep working. (Task 2.)
5. **The frame URL never carries the token twice** → `frameSrc` replaces an existing `tmFrame` instead of appending. (Task 1.)

### Task 1: Layout model (framework-free)

**Files:**
- Create: `src/lib/multiLayout.ts`, `src/lib/multiLayout.test.ts`

**Interfaces:**
- Produces:
  - `export const DEMO_LOGINS = ['admin', 'tata', 'starsi', 'mladsi'] as const; export type DemoLogin = (typeof DEMO_LOGINS)[number]`
  - `export const SIZES = { phone: { w: 390, h: 844, scale: 1 }, small: { w: 360, h: 740, scale: 1 }, tablet: { w: 820, h: 1180, scale: 0.7 } } as const; export type SizeKey = keyof typeof SIZES`
  - `export interface Device { id: string; user: DemoLogin; size: SizeKey; path: string; token: string | undefined }`
  - `export const DEFAULT_LAYOUT: readonly Device[]` → tata, starsi, mladsi, all `phone`, path `/`, no token (ids `d1`..`d3`)
  - `export function parseLayout(raw: string | null): Device[]` — invalid JSON / not an array / empty → a copy of `DEFAULT_LAYOUT`; drops entries with an unknown user or size; `path` through `safePath` (`null` → `/`); `token` kept only if a non-empty string
  - `export function serializeLayout(devices: readonly Device[]): string`
  - `export function safePath(input: string): string | null` — trims; `''` → `'/'`; resolved against `https://x` it must keep origin `https://x` (so `//evil`, `https://evil.example/x`, `javascript:` → `null`); returns `pathname + search + hash` with any `tmFrame` param removed; a bare `ukoly` → `/ukoly`
  - `export function frameSrc(device: Device): string` — `safePath(device.path) ?? '/'` with `tmFrame=<token ?? '-'>` set (replacing any existing)
  - `export function frameName(token: string | undefined): string` → `tm-frame:` + (token ?? '')
  - `export function tokenFromName(name: string): string | undefined | null` → `null` if not a frame name, `undefined` for `tm-frame:`, else the token
  - `export function newDeviceId(devices: readonly Device[]): string` → `d<n>` one past the highest

  - `parseLayout(null)`, `parseLayout('{')`, `parseLayout('[]')`, `parseLayout('{"a":1}')` → equal to `DEFAULT_LAYOUT`
  - keeps valid entries and drops `{ user: 'mama' }` and `{ size: 'watch' }` from a mixed list
  - round trip: `parseLayout(serializeLayout(x))` equals `x` for a 2-device list with tokens
  - `safePath`: `''`→`'/'`, `'ukoly'`→`'/ukoly'`, `'/ukoly?a=1#x'`→`'/ukoly?a=1#x'`, `'/?tmFrame=abc&b=2'`→`'/?b=2'`, `'//evil.example/x'`→`null`, `'https://evil.example/x'`→`null`, `'javascript:alert(1)'`→`null`

  - `newDeviceId(DEFAULT_LAYOUT)`→`'d4'`; `newDeviceId([])`→`'d1'`

### Task 2: Per-frame login state

**Files:**
- Create: `src/lib/multiLogin.ts`, `src/lib/multiLogin.test.ts`

**Interfaces:**
- Consumes: `Device`, `DemoLogin` (Task 1); `FrameLoginResult` type from `~/server/auth/frameLogin` (type-only import).
- Produces:
  - `export type FrameStatus = { kind: 'loggingIn' } | { kind: 'ready' } | { kind: 'failed' }`
  - `export async function logInDevice(device: Device, login: (username: DemoLogin) => Promise<FrameLoginResult>): Promise<{ device: Device; status: FrameStatus }>` — `ok` → `{ device: { ...device, token }, status: { kind: 'ready' } }`; not ok, or a rejected promise → `{ device: { ...device, token: undefined }, status: { kind: 'failed' } }`
  - `export function needsLogin(device: Device): boolean` → `device.token === undefined`

**Files:**

**Interfaces:**
- Consumes: Tasks 1–2, `frameLoginFn` (`~/server/auth/functions`), `getDevPagesAllowed` (`~/server/env/functions`).
- Page behaviour:
  - State: `devices` (from `parseLayout(localStorage)` on mount, saved with `serializeLayout` after each change), `status` per device id, `activeId`, `reloadKey` per device id.
  - On mount and whenever a device `needsLogin`, run `logInDevice` for it. A device that already has a stored token is rendered at once; a dead stored token simply shows the app's own login screen inside the frame, like a phone.
  - **Toolbar:** title, `add` (opens `AddDevice`: user `Select`, size `Select`, `cancel` / `confirmAdd`; new device path `/`), `reloadAll`, the `remembered` note.
  - **DeviceFrame header:** user `Select` (change → token cleared → new login), size `Select`, `reload` icon button (`RotateCw`, `aria-label`), `remove` icon button (`X`, `aria-label`), address `Input` (shows `device.path`; Enter → `safePath`; `null` leaves it unchanged; else set path + bump `reloadKey`).
  - **iframe:** `key={reloadKey}`, `name={frameName(token)}`, `src={frameSrc(device)}`, `title` = the user's name, size from `SIZES`; tablet wrapped in a box with `transform: scale(0.7)` (origin top left) and the box sized to the scaled size. `onLoad`: read `contentWindow.location` (same origin; try/catch) → `path = safePath(pathname + search + hash)`, and `tokenFromName(contentWindow.name)` → store the frame's current token (Review Focus 1).
  - **reload / reloadAll:** for each device, first read its current token back from `contentWindow.name` (as in onLoad), then bump `reloadKey`.
  - **Active ("v ruce"):** on `window` `blur`, if `document.activeElement` is one of the iframes, set `activeId` to it; the active frame gets the accent outline + a small `inHand` badge (`motion-reduce:transition-none` on the outline transition).
  - **States:** `loggingIn` → frame area shows `loggingIn` instead of the iframe; `failed` → `loginFailed` + `retry` (re-runs the login for that device only); no devices → `empty` with the `add` button.
  - Removing a device needs no confirmation: adding it again undoes it (no data lost; its session stays in the DB like any idle session).
  - Layout: toolbar on top; frames in a horizontal `flex` row with `gap`, `overflow-x: auto` on that row only (the page body never scrolls sideways); each header is exactly its frame's width; header controls wrap to two lines at 360 px.
  - Tap targets: every button and select uses the existing 44 px sizes (`size="icon"` → `size-tap`, `min-h-tap`).

## UX pre-flight (pr-review-rounds §1)

- Tap targets 44 px: all buttons/selects via existing `size-tap` / `min-h-tap` (Task 3).
- Motion: only the active outline transitions; `motion-reduce:transition-none`.
- Busy + error + retry: `loggingIn`, `failed` + `retry` per frame (Tasks 2–3).
- Empty state: no devices → `empty` + `add` (Task 3).
- Irreversible action: none (remove is undone by adding again) → no Dialog.
- Long names at 360 px: the user names are short and fixed; the address input cuts with an ellipsis and scrolls inside itself; header controls wrap.
- Phone keyboard rule: this is a desktop dev tool, not a phone screen; its only text field is the address input in a frame header, so no `e2e/keyboard.spec.ts` case **[ruling, goes in the brief]**.
