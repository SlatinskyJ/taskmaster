# Moje row chip at 360 px Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Issue:** [#148 Brother's "Moje" row cuts the state chip at 360 px](https://github.com/SlatinskyJ/taskmaster/issues/148)

**Goal:** On a taker's Domů, a reserved task under "Moje" shows its whole name (up to two lines) and its whole state chip "Rezervováno" at 360 px.

**Architecture:** Same fix as PR #135 for "Ke schválení": the secondary action becomes a 44 px icon button. "Uvolnit" turns into a ghost icon button (lucide `Undo2`, `aria-label="Uvolnit"`); "Hotovo" stays a text button, because it is the main action and the mockup `Main` draws it with its label. `TaskRow` is not touched (its chip/meta wrap from #135 already works once the row has room).

**Tech Stack:** React, Tailwind v4, lucide-react, Vitest (`renderToStaticMarkup`).

**Spec:** UI doc `docs/superpowers/specs/2026-11-16-taskmaster-ui-design.md` §1 (360 px, tap ≥ 44 px), §5 (buttons: icon 44 px), §7.1 (`Main`); spec §5.4 (release a reservation). No behaviour change: same server calls, same toasts.

**Size:** about 15 changed lines in `src/components/tasks/TakerBoard.tsx`, plus tests. No new strings, no new dependency (lucide-react is already used by `ToApprove`).

## Global Constraints

- UI labels Czech, from `src/lib/strings.ts` only (`cs.work.release` = "Uvolnit", `cs.work.done` = "Hotovo"). No new strings.
- Tap targets ≥ 44 px: icon button uses `size="icon"` (`size-tap`).
- An icon-only button carries its Czech name in `aria-label`; the icon is `aria-hidden`.

## Evidence (taken before planning)

Demo data, `mladsi` at 360 px, task "Vyluxovat celý obývák a chodbu" (3 b) reserved:

- Today: name cut to "Vyluxovat / celý obývák …", chip cut to "Rezervová…" (two text buttons ≈ 170 px).
- With "Uvolnit" swapped for a 44 px icon button in the browser: name reads in two lines, chip reads "Rezervováno" in full, "Hotovo" in full.

## Layout at 360 px (UX pre-flight)

| Part | At 360 px with a long Czech name |
| --- | --- |
| Name | wraps to 2 lines, then ellipsis (`line-clamp-2`, unchanged) |
| Chip "Rezervováno" | whole; cut only if wider than the text column alone (unchanged #135 rule) |
| Points | whole (`whitespace-nowrap`, unchanged) |
| ↶ Uvolnit | 44 × 44 icon button, ghost |
| Hotovo | text button, `min-h-tap`, whole |

- Busy state: both buttons `disabled` while any action runs (unchanged); add `aria-busy` on Uvolnit while its release runs (Hotovo already has it). Errors: `useTaskAction` already shows a Czech toast and the buttons come back (unchanged).
- Releasing can be undone (reserve again), so no confirm dialog (unchanged).
- No animation added.
- "Volné" row (one "Rezervovat" button) and the pending "Moje" row (no buttons) are not changed.

## Review Focus

1. Screen reader / long-press: the icon button must still announce "Uvolnit" (aria-label test).
2. Two-digit points ("18") on the same row: check the chip still reads whole in a screenshot.
3. A double tap during a running release: both buttons disabled (test with `busy = 'release-1'`).
4. Icon confusion with ✕ Zamítnout on the giver's row: use `Undo2`, not `X`, so "give back" never looks like "reject" (test asserts `lucide-undo-2`, not `lucide-x`).
5. Hotovo must not lose its label (test asserts visible text "Hotovo").

```ts
it('shows ↶ Uvolnit as a 44 px icon button and keeps Hotovo as text', () => {
  action.busy = null
  const html = renderToStaticMarkup(<TakerBoard items={[reserved]} me={4} />)
  const release = byLabel(html, cs.work.release)
  expect(release).toContain('size-tap')
  expect(release).toContain('lucide-undo-2')
  expect(release).not.toContain('lucide-x')
  expect(release).not.toMatch(/>Uvolnit</)
  const done = buttons(html).find((b) => b.includes(`>${cs.work.done}<`)) ?? ''
  expect(done).toContain('bg-ok')
  expect(done).toContain('min-h-tap')
  expect(html).toContain(cs.state.reserved)
})

it('disables both buttons and marks Uvolnit busy while a release runs', () => {
  action.busy = 'release-1'
  const html = renderToStaticMarkup(<TakerBoard items={[reserved]} me={4} />)
  const release = byLabel(html, cs.work.release)
  expect(release).toMatch(/<button[^>]*disabled/)
  expect(release).toMatch(/<button[^>]*aria-busy="true"/)
  const done = buttons(html).find((b) => b.includes(`>${cs.work.done}<`)) ?? ''
  expect(done).toMatch(/<button[^>]*disabled/)
  expect(done).not.toContain('aria-busy="true"')
})
```
