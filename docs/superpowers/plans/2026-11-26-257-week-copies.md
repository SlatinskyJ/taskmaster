# Week chore copies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With the new launch switch `weekPlan` on, every schedule slot of the running week gets its chore copy the moment the week starts, and each copy belongs to its Prague day (#257).

**Architecture:** One new nullable column `tasks.plan_day_at` (the UTC instant its Prague day starts) marks a copy made under the week-plan rules; null = old rules. The domain `Item` gets a `day` window that only `toItem(row, true)` fills, so the day rules (no Hotovo before the day, no-deadline copy expires at midnight) apply only to marked rows *and* only while the switch is on (spec: switch off = old rules). A new server module `weekCopies.ts` makes the copies up to the horizon; the scheduler, the settlement and a template agreement call it.

**Tech Stack:** TanStack Start, Drizzle + SQLite (better-sqlite3), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-design.md` §5.3, §5.12 (and §5.8 for periods). Issue: [#257](https://github.com/SlatinskyJ/taskmaster/issues/257).

## Global Constraints

- UI labels Czech, only in `src/lib/strings.ts`; code, DB, logs English.
- All Prague wall-clock maths through `src/domain/dates.ts`; store UTC with `toIsoUtc`.
- `src/domain/` stays framework-free.
- Every state change writes its audit entry in the same transaction (`writeAudit` / `runStep`).
- Never edit a committed migration; `pnpm db:check` must pass.
- New switch `weekPlan`: seed row OFF in production; on in `demo` and in the e2e seed of this PR.
- Spec values: copies from the period's start up to its cutoff; **at most 14 days ahead** of now; one copy per slot; deadline counted from the slot; catch-up after downtime: only the latest missed slot.

## Decisions (builder rulings, for the brief)

1. **Marker column, not a flag on read alone.** `plan_day_at` is written only for copies made while the switch is on (scheduled week copies and on-demand copies). Copies made before the flip keep null and so keep the old rules forever (spec "copies made before the flip keep the old rules").
2. **Switch off = old rules for every copy**: the day rules are applied only when `getFlags(db).weekPlan` is on at the moment of the step/read. Turning the switch on again re-applies them to marked copies.
3. **A future copy's `created_at`** is the moment it was made (`min(slot, now)`), not its slot: a row is never "made in the future". Its deadline and its day come from the slot.
4. **Copies' lower bound** is `max(template.agreedAt, period.startsAt)`, and nothing at or before `template_slots.last_slot_at` is made again. A slot of the old period after a settlement (Sunday 21:00) was made by the old period's run and is not made again (spec [call]).
5. **No running period** (before the first roll): no copies. The tick order (periods job first) means the first tick after a cutoff rolls, then copies.
6. **Domů / Úkoly / Schůzka list**: with the switch on, a marked copy is listed only from the start of its day; on Domů a *reserved* later copy is still listed (Moje rezervace shows its weekday, e.g. "Čt"), without Hotovo. The task page of a later copy shows Rezervovat / Uvolnit but not Hotovo.
7. **No CHECK constraint** on `plan_day_at` (SQLite would need a table rebuild); only scheduler and on-demand code write it.

## Review Focus

1. A settlement on Sunday 20:00 must make Monday-to-Sunday copies in the same transaction; a copy for Sunday 21:00 made by the old week must not be made twice → test in Task 4.
2. Server down for two days, then a tick: only the latest missed slot gets a copy, the future slots all do → test in Task 3.
3. A no-deadline copy for yesterday still open at 00:05 must expire (system, audited) and must not block Zapsat today → tests in Tasks 5 and 6.
4. Switch flipped off with marked copies still open: they never expire at midnight and Hotovo works before their day → test in Task 2 and Task 5.
5. A period longer than 14 days: copies only up to now + 14 days, the rest appear as ticks move on → test in Task 3.

## Tests and UX pre-flight

- **Audit rollback:** Task 3 `a failed audit write leaves no copy and no template_slots row for that template, and the other templates still get theirs` (stub `writeAudit` to throw for one template); Task 5 `a failed audit write on the midnight expiry leaves the copy open`.
- **Boundaries:** Task 2 tests `before_day` at the day's first millisecond minus 1 and at it, and expiry at `endsAt - 1 ms` and at `endsAt`; Task 3 tests a slot exactly at `until` (not made) and exactly at `at + 14 days` when that is before the cutoff (not made, half-open), a slot exactly at `at` (counts as past: it is the catch-up slot); Task 6 tests a copy whose day starts exactly now (listed).
- **Wrong actor:** Task 2 `a giver's Hotovo before the day is refused too (before_day applies to everyone)`; `expireItem by a person is refused (not_allowed)` stays.
- **Real entry points:** Task 4 runs the copies through `schedulerJobs(db, …)` (the `instances` job by name) and the settlement through `settleNow`; Task 5 runs Zapsat through `selfLogInstance` and the tiles through `listLoggableTemplatesFn`'s handler module (`listLoggableTemplates`); Task 6 runs Domů through `listBoardFn`'s `shown(db)` path (`functions.test.ts`).

- **UX:** the only screen change is a Moje rezervace row (TakerBoard) and the task page buttons. ### Task 3: Make the week's copies

**Files:**
- Create: `src/server/instances/weekCopies.ts`, test `src/server/instances/weekCopies.test.ts`
- Modify: `src/server/instances/instances.ts` (`InstanceBirth` gains `planDayAt?: Date`, written to the row and to the birth entry's `after` as `planDayAt`), `src/server/instances/index.ts` (export)
- Modify: `src/server/tasks/item.ts`: `toItem(row: TaskRow, dayRules = false): Item` → `day: dayRules && row.planDayAt ? copyDay(parseIsoUtc(row.planDayAt)) : null`

**Interfaces (produces):** `makeWeekCopies(db: Db | Tx, at: Date, opts?: { templateId?: number; log?: Pick<Console, 'error'> }): TaskRow[]`.

Algorithm: `period = currentPeriod(db, at)`; none → `[]`. `until = min(period.cutoffAt, at + 14 × 24 h)`. For each active template with a schedule and `agreedAt` (only `opts.templateId` if given), one `db.transaction` per template (one failing leaves the rest, logged `[scheduler] week copies: template <id> failed`): `weekSlots({ schedule, from: max(agreedAt, period.startsAt), lastSlotAt, at, until })`; for each slot: `createInstance(SYSTEM, 'scheduled', approvalRequired, rule ? instanceDeadline(rule, slot) : null, copyDay(slot))`, `insertInstance(tx, { actor: system, createdBy: template.createdBy, createdAt: min(slot, at), loggedAt: at, planDayAt: startOfPragueDay(slot) }, template, 'scheduled', item, { slotAt })`; a copy already over (grace ended, or no deadline and its day ended) is expired at once with `expireTask(tx, id, at)`. Then upsert `template_slots.last_slot_at` = the last slot made. No "skip while one is open" (spec §5.12). Must not import `~/server/templates/templates` beyond the pure `scheduleOf` / `deadlineRuleOf` already used by `scheduled.ts`.
