# Week chore copies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With the new launch switch `weekPlan` on, every schedule slot of the running week gets its chore copy the moment the week starts, and each copy belongs to its Prague day (#257).

**Architecture:** Two new columns on `tasks`: `plan_day_at` (the UTC instant the copy's Prague day starts; kept for good, the table in #258 places copies by it) and `week_rules` (boolean: the day rules apply to this copy). The domain `Item` gets a `day` window that only `toItem(row, true)` fills, and only for rows with `week_rules` on; callers decide `dayRules` from the switch at their entry point (server functions, scheduler jobs, settlement), never inside `runStep`. When the switch is off, the scheduler's first tick turns `week_rules` off on every open or reserved copy (audited), so a later flip on never re-applies the rules to them (spec: copies made before the flip keep the old rules). A new server module `weekCopies.ts` makes the copies up to the horizon; the scheduler, the settlement and a template agreement call it.

**Tech Stack:** TanStack Start, Drizzle + SQLite (better-sqlite3), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-design.md` §5.3, §5.12 (and §5.8 for periods). Issue: [#257](https://github.com/SlatinskyJ/taskmaster/issues/257).

## Global Constraints

- UI labels Czech, only in `src/lib/strings.ts`; code, DB, logs English.
- All Prague wall-clock maths through `src/domain/dates.ts`; store UTC with `toIsoUtc`.
- `src/domain/` stays framework-free.
- Every state change writes its audit entry in the same transaction (`writeAudit` / `runStep`).
- Never edit a committed migration; `pnpm db:check` must pass.
- New switch `weekPlan`: seed row OFF in production; on in `demo` and in the e2e seed of this PR.
- Spec values: copies from the period's start up to its cutoff; **at most 14 days ahead** of now; one copy per slot; deadline counted from the slot; catch-up after downtime: only the latest missed slot.

## Decisions (builder rulings, for the brief)

1. **Marker columns, not a flag on read alone.** `plan_day_at` and `week_rules = 1` are written only for copies made while the switch is on (scheduled week copies and on-demand copies). Copies made before the flip have neither and keep the old rules forever (spec "copies made before the flip keep the old rules").
2. **Switch off = old rules, for good.** While the switch is off every read and step applies no day rules (entry points pass `dayRules: false`). The scheduler's `weekRules` job, on the first tick with the switch off, sets `week_rules = 0` on every open or reserved copy that has it, one transaction per copy, audit `instance.week_rules_dropped` (actor system, before/after `weekRules`). So on → off → on never brings the rules back to a copy made in an earlier on-spell (Rules judge, round 1). `plan_day_at` stays, so the copy keeps its day for display.
3. **A future copy's `created_at`** is the moment it was made (`min(slot, now)`), not its slot: a row is never "made in the future". Its deadline and its day come from the slot.
4. **Copies' lower bound** is `max(template.agreedAt, period.startsAt)`, and nothing at or before `template_slots.last_slot_at` is made again. A slot of the old period after a settlement (Sunday 21:00) was made by the old period's run and is not made again (spec [call]).
5. **No running period** (before the first roll): no copies. The tick order (periods job first) means the first tick after a cutoff rolls, then copies.
6. **Domů / Úkoly / Schůzka list**: with the switch on, a marked copy is listed only from the start of its day; on Domů a *reserved* later copy is still listed (Moje rezervace shows its weekday, e.g. "Čt"), without Hotovo. The task page of a later copy shows Rezervovat / Uvolnit but not Hotovo.
7. **No CHECK constraint** on the new columns (SQLite would need a table rebuild); only scheduler and on-demand code write them.
8. **After its day** a no-deadline copy can be neither reserved nor done (`past_grace`), even in the minutes before the expiry tick runs (Rules judge, round 1). A deadline copy follows its grace window.
9. **Sort order:** copies made together at a week start share one `created_at`; every list touched here sorts by `id` (or `completed_at`), not `created_at`, so their order is slot order.

## Review Focus

1. A settlement on Sunday 20:00 must make Monday-to-Sunday copies in the same transaction; a copy for Sunday 21:00 made by the old week must not be made twice → test in Task 4.
2. Server down for two days, then a tick: only the latest missed slot gets a copy, the future slots all do → test in Task 3.
3. A no-deadline copy for yesterday still open at 00:05 must expire (system, audited) and must not block Zapsat today → tests in Tasks 5 and 6.
4. Switch flipped off with marked copies still open: they never expire at midnight and Hotovo works before their day, also after the switch is turned on again → tests in Tasks 5 and 5b.
5. A period longer than 14 days: copies only up to now + 14 days, the rest appear as ticks move on → test in Task 3.

**Interfaces (produces):** `makeWeekCopies(db: Db | Tx, at: Date, opts?: { templateId?: number; log?: Pick<Console, 'error'> }): TaskRow[]`.

Algorithm: `period = currentPeriod(db, at)`; none → `[]`. `until = min(period.cutoffAt, addPragueDays(at, 14))`. For each active template with a schedule and `agreedAt` (only `opts.templateId` if given), one `db.transaction` per template (one failing leaves the rest, logged `[scheduler] week copies: template <id> failed`): `weekSlots({ schedule, from: max(agreedAt, period.startsAt), lastSlotAt, at, until })`; for each slot: `createInstance(SYSTEM, 'scheduled', approvalRequired, rule ? instanceDeadline(rule, slot) : null, copyDay(slot))`, `insertInstance(tx, { actor: system, createdBy: template.createdBy, createdAt: min(slot, at), loggedAt: at, planDayAt: startOfPragueDay(slot) }, template, 'scheduled', item, { slotAt })` (`planDayAt` set → the row also gets `week_rules = 1`); a copy already over (grace ended, or no deadline and its day ended) is expired at once with `expireTask(tx, id, at, true)`. Then upsert `template_slots.last_slot_at` = the last slot made. No "skip while one is open" (spec §5.12). Imports `scheduleOf` / `deadlineRuleOf` from `~/server/templates/rules` (Task 4 step 0), never from `templates.ts`.
