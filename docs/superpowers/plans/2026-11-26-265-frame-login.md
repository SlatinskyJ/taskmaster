# Per-frame login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (CLAUDE.md PR flow). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On dev and PR previews, a request from a viewer frame uses that frame's own session token instead of the shared session cookie, so `/dev/multi` (next PR) can show several users at once. Production behaves exactly as today.

**Architecture:** One framework-free module decides "is this request a frame, and which token" from the request (header, query, `Sec-Fetch-Dest`) and the env guard `devPagesAllowed`. `src/server/auth/http.ts` routes every cookie read/write through it: in a frame the cookie is never read, set or cleared, and a new login hands its token back in the server function result. On the client, a global function middleware (new `src/start.ts`) adds the frame header from `window.name`; the login and logout screens store the returned token there. A preview-only `frameLoginFn` lets the viewer log a demo user in for a frame.

**Tech Stack:** TanStack Start 1.169 (`createStart`, `createMiddleware`, `createCsrfMiddleware`), Vitest, existing auth module.

**Spec:** `docs/superpowers/specs/2026-11-26-multi-user-viewer-design.md` (+ §6 "Multi-user viewer" bullet in `2026-11-16-taskmaster-design.md`). Issue: #265. This is PR 1 of 2 (PR 2: the `/dev/multi` page + e2e; `Part of #265` here, `Closes #265` there).

## Global Constraints

- Frame handling exists **only when `devPagesAllowed(process.env)`** (`src/server/env/devPages.ts`). Otherwise frame headers/query are ignored and the cookie is the only way in.
- A frame request never reads, sets or clears `__Host-tm_session`, also when it has no token or a dead one (design: "never falls back to the page's cookie").
- Frame tokens are ordinary sessions: same table, `createSession`, 90-day sliding expiry, same logout. No new login method, no schema change, no migration.
- Logging in inside a frame (password or passkey) logs in that frame only (Jakub, 2026-11-26).
- Every state change keeps its audit entry (login/logout already audit; nothing new changes state except `frameLoginFn`, which goes through `login()`).
- CLAUDE.md / auth README: whoever adds `src/start.ts` must add `createCsrfMiddleware()` there.
- Code, identifiers, logs in English; no new Czech UI text in this PR.

## Review Focus

1. **Production env with a forged `x-tm-frame` header** → ignored; the cookie user is used, cookie behaviour unchanged. (Task 1 + Task 2 tests.)
2. **A frame with no token, or an expired/unknown token** → nobody signed in, and the page cookie is neither used nor cleared. (Task 2.)
3. **Document load in a frame without the query** (e.g. the service worker's `location.replace`) → `Sec-Fetch-Dest: iframe` still marks it a frame, so it shows logged out rather than the page's user. (Task 1.)
4. **Changing your own password inside a frame** keeps that frame's session and logs out the others (it reads `sessionToken()`). (Task 2: `sessionToken()` returns the frame token.)
5. **CSRF still enforced** after adding `src/start.ts` (a cross-site server function POST is refused). (Task 4.)

### Task 1: Frame detection (framework-free)

**Files:**
- Create: `src/server/auth/frame.ts`
- Test: `src/server/auth/frame.test.ts`

**Interfaces:**
- Produces:
  - `export const FRAME_HEADER = 'x-tm-frame'` (value: the token, or `''` for a frame with none)
  - `export const FRAME_QUERY = 'tmFrame'` (document loads only; same meaning)
  - `export type FrameRequest = { inFrame: false } | { inFrame: true; token: string | undefined }`
  - `export function readFrame(env: NodeJS.ProcessEnv, req: { header: string | undefined; query: string | undefined; fetchDest: string | undefined }): FrameRequest`

Rules: not `devPagesAllowed(env)` → `{ inFrame: false }`. Else header present → frame, token = header (empty → `undefined`); else query present → same from query; else `fetchDest === 'iframe'` → `{ inFrame: true, token: undefined }`; else not a frame.

  - `it('preview: empty header is a frame with no token')` → `{ inFrame: true, token: undefined }`
  - `it('preview: query on a document load')`: header undefined, query `'q'` → token `'q'`
  - `it('preview: an iframe load without header or query is a frame with no token')`
  - `it('preview: a normal request is not a frame')`: all undefined, fetchDest `'document'` → `{ inFrame: false }`
