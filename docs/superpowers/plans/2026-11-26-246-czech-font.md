# Czech letters in one font: Baloo 2 for words, Fredoka for numbers — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Issue:** [#246 Fix hard-to-read font and Czech letters](https://github.com/SlatinskyJ/taskmaster/issues/246)

**Goal:** Every Czech letter on every screen is drawn by one of the app's own fonts, never by a system fallback.

**Cause (checked):** Fredoka (`@fontsource-variable/fredoka` 5.3.0, every subset) has no glyph for `ě č ř ů ť ď ň Ě Č Ř Ů Ť Ď Ň`. Headings, buttons, tabs, card/sheet/dialog titles, toasts, avatars and `num` use Fredoka, so those letters come from a system font ("Hotovo bez bodů", "Odpovědět", "Příští týden"). `@fontsource-variable/baloo-2` 5.3.0 latin + latin-ext covers every Czech letter (checked with fontTools).

**Decision (Jakub, project thread 2026-11-26 10:28 Prague, after side-by-side screenshots):** option 2 = **Baloo 2** for everything Fredoka draws today except numbers; **Fredoka stays for numbers** (`num`). Nunito stays the body font.

**Architecture:** Font tokens plus one `@font-face`. `--font-display` points at Baloo 2. Fredoka is used **for digits only**: an own face `Fredoka Digits` (the fontsource Fredoka latin file, `unicode-range: U+0030-0039`), and `num` uses `'Fredoka Digits', 'Baloo 2 Variable', …`. So in a `num` line like "Celkem 108 · odečteno 100" the digits are Fredoka and **every letter** is Baloo 2: no word is drawn in two fonts (plan round 1, UX). The fontsource `fredoka/wght.css` import goes away (nothing else names Fredoka). No component changes besides one conflicting class.

**Tech Stack:** Tailwind v4 `@theme` tokens, fontsource variable fonts, Playwright + Chrome DevTools Protocol for the test.

**Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-ui-design.md` §2.3 (type) and §3 (points line "in Fredoka"). §2.3 says "Fredoka for headings and all numbers"; Jakub's decision changes the headings half. That doc line is changed in a **separate docs PR** (not in this PR, CLAUDE.md "never fix the spec inside a PR"); this PR links it.

**Size:** about 10 changed lines of source (CSS tokens, one import, one class, package.json), plus one e2e spec (~70 lines), one suite row, the lockfile.

- [ ] **Step 1: Write the test**

`e2e/fonts.spec.ts`, comment on top: Czech letters must come from the app's fonts; Fredoka only for digits (#246).

Helper `scanFonts(page): Promise<Scan[]>` with `interface Scan { text: string; isNum: boolean; fonts: { familyName: string; isCustomFont: boolean; glyphCount: number }[] }`:
- in the page, mark every visible element (`checkVisibility()`) whose **own text nodes** (trimmed, joined) contain a letter `/\p{L}/u` or a digit with `data-font-scan="<i>"`; record its own text and `classList.contains('num')`;
- CDP (`page.context().newCDPSession(page)`; `DOM.enable`, `CSS.enable`, `DOM.getDocument`, `DOM.querySelectorAll('[data-font-scan]')`), `CSS.getPlatformFontsForNode` for each.

Pure checks (same file):
- `systemFallbacks(scans)`: `"<text ≤30>: <family>"` for each font with `isCustomFont === false` among scans whose text has `/[ěščřžýáíéůúťďňĚŠČŘŽÝÁÍÉŮÚŤĎŇ]/`;
- `mixedWords(scans)`: for each `isNum` scan whose text has a letter, the Fredoka glyph count (families matching `/Fredoka/`) must equal its number of digits `[0-9]`; else `"<text>: <n> Fredoka glyphs for <d> digits"`.

`async function ready(page, path, mustSee: string)`: `goto(path)`, `await expect(page.locator('main')).toContainText(mustSee)`, `await page.evaluate(() => document.fonts.ready)`.

Tests (each logs in with `passwordLogin(page, 'tata')` then `await expect(page).toHaveURL(/\/$/)`, except login):
```ts
const SCREENS = [
  ['/', 'Ke schválení'],          // exact strings: take them from cs.* in src/lib/strings.ts
  ['/ukoly', 'Hotovo bez bodů'],
  ['/tyden', 'Příští týden'],
  ['/schuzka', <a demo row>],
  ['/profil', <displayName 'Táta'>],
] as const
for (const [path, mustSee] of SCREENS) test(`${path}: Czech letters in app fonts`, …
  const scans = await scanFonts(page)
  expect(scans.map((s) => s.text)).toContainEqual(expect.stringContaining(mustSee))
  expect(systemFallbacks(scans)).toEqual([])
  expect(mixedWords(scans)).toEqual([])
```
- `login`: `goto('/login')`, mustSee = `cs.login.submit` ("Přihlásit"), same three asserts.
- `Týden history: digits Fredoka, words Baloo 2`: `/tyden`, click tab `cs.week.history`, wait for text `odečteno`; assert scans contain an `isNum` row with `odečteno`, `mixedWords` and `systemFallbacks` empty, and that row's fonts include both `/Fredoka/` and `/Baloo/`.
- `headings Baloo 2, numbers Fredoka`: `/ukoly`; the `h1` scan's families equal `[expect.stringMatching(/Baloo/)]`; a `main .num` digits-only scan's families equal `[expect.stringMatching(/Fredoka/)]`.
- `ScoreDial digits are Fredoka`: `/ukoly`, open the new-task sheet (`cs.*` label of "+ Nový"), wait for the dial; the dial's number scan families equal `[expect.stringMatching(/Fredoka/)]` (catches `font-display` coming back on ScoreDial).

The empty-list asserts never pass on an empty scan: each test first asserts its `mustSee` text was scanned.

### Task 2: Baloo 2 for words, Fredoka for numbers

- Modify: `src/styles/app.css`: replace `@import '@fontsource-variable/fredoka/wght.css';` with `@import '@fontsource-variable/baloo-2/wght.css';`, and add the `Fredoka Digits` face (checked: Vite resolves the package path and fingerprints the file):

  ```css
  /* Fredoka draws digits only: it has no ě č ř ů ť ď ň (#246). */

    font-family: 'Fredoka Digits';
    font-style: normal;
    font-display: swap;
    font-weight: 300 700;
    src: url('@fontsource-variable/fredoka/files/fredoka-latin-wght-normal.woff2') format('woff2-variations');
    unicode-range: U+0030-0039;
  }
  ```
- Modify: `src/styles/theme.css:196` and the `num` utility
