# Demo mode on the server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `TASKMASTER_ENV=demo` turns on the demo seed and dev pages, and makes the server refuse
the locked actions, strip links from input, keep passkeys off, skip the per-username failure
limit for demo accounts, and cap login attempts and live streams per IP. Issue #327 (epic #322).

**Architecture:** One helper `isDemo(env)` in `src/server/env/demo.ts`; every demo branch checks it.
The lock is a function middleware `demoLock` added to the locked server functions. Link removal is
a global function middleware with a server-side validator in `src/start.ts`, so it runs before
every server function's own validator. Caps are small in-memory counters in `src/server/demo/caps.ts`
(lost on restart, which is fine for a demo).

**Tech Stack:** TanStack Start (function middleware), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-27-demo-environment-design.md`, main spec §6 bullet
"Public demo".

## Global Constraints

- Every demo branch checks `TASKMASTER_ENV === 'demo'` exactly; `preview` keeps today's behaviour.
- The demo seed and frame login keep refusing when `ADMIN_PASSWORD` is set.
- Links removed: every run starting with `http://`, `https://` or `www.` (case-insensitive) up to
  the next whitespace. Plain `name.cz` stays. Silent.
- Caps and the per-username exemption apply only on the demo; production unchanged.
- Czech UI text only in `src/lib/strings.ts`; code/identifiers English. No screen changes in this PR
  (screens are #328).
- Lock refusals change no state, so they write no audit entry.

## Review Focus

1. A link glued to text, `viz:https://x.cz,` or `WWW.X.CZ`: removed up to whitespace, the rest kept.
   Test in Task 3.
2. Nested input (an object holding an array of strings, e.g. a week plan): every string stripped,
   numbers/booleans/null untouched. Test in Task 3.
3. Link removal leaves an empty required field (`https://x.cz` as a task title): the function's own
   validator then rejects it as empty, as for blank input. e2e in Task 5.
4. Preview with `TASKMASTER_ENV=preview`: no lock, no stripping, no caps. Tests in Tasks 2-4 call
   each helper with `preview` and expect today's behaviour.
5. Demo with `WEBAUTHN_RP_ID` set by mistake: passkeys still off. Test in Task 1.
