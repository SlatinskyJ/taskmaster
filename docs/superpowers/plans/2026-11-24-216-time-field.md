# Fit the time field inside its card on iPhone: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Issue:** #216 Fit the time field inside the Výchozí týden card on iPhone.

**Goal:** Time (and date) fields keep the width their layout gives them on iOS, so the Konec row on Správa → Výchozí týden fits inside its card.

**Architecture:** iOS WebKit draws `<input type="time">` with its native appearance and a minimum width of its own, ignoring `min-width: 0` and the grid column. Turning the native appearance off (`appearance: none`) makes WebKit respect the width; the value is then left-aligned like the other fields. The fix goes into the shared `Input` component for `type="time"` and `type="date"`, so every time field gets it: Výchozí týden (`DefaultWeekCard`), Příští týden (`NextWeekForm`) and opakované úkoly (`RecurringFields`).

**Tech Stack:** React 19, Tailwind v4, Vitest (node env, `renderToStaticMarkup`).

**Spec:** issue #216 (Jakub's iPhone screenshot, 2026-11-24).

## Global Constraints

- No Czech text change, no new dependency.
- Shared module (`src/components/ui/input.tsx`): other input types render exactly as before.
- The picker must still open on tap (iOS keeps the wheel picker with `appearance: none`).

## Review Focus

1. Other input types (text, password, checkbox) unchanged. Pinned by Task 1's "text field keeps its look" test.
2. Chromium (desktop, Android) still opens its picker on tap with `appearance-none`. Checked on the preview.
3. Value alignment: WebKit centres the value once the appearance is off; `[&::-webkit-date-and-time-value]:text-left` keeps it left like other fields.
4. Height stays `min-h-tap` (44 px). Asserted in Task 1.
5. Real iPhone: no automated WebKit here (Playwright has only Chromium in CI), so Jakub checks the Výchozí týden row on the preview. Stated in the brief.
