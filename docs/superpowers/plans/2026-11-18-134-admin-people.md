# Admin screen: people — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Issue:** #134 Admin screen: people (split out of #47). **Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-design.md` §3 (admin), §6 (admin console, reset ends sessions); UI doc `docs/superpowers/specs/2026-11-16-taskmaster-ui-design.md` §7.5 ASettings (people part).

**Goal:** on Správa the admin adds a person (name, login name, role, starting password), renames them, changes their role, and resets their password.

**Architecture:** the DB layer exists (`src/server/users/manage.ts`: `createUser`, `updateUser`, `setPasswordHash`, each one transaction with its audit entry and the people-change hooks). This PR adds a thin server module that checks and hashes the password and calls those, three admin-only server functions, and two dialogs on the existing Správa screen. No schema, no migration, no new dependency.

**Tech stack:** TanStack Start server functions, Drizzle/SQLite, `@node-rs/argon2` via `~/server/auth/password`, React + `Drawer` (vaul), `Dialog`, `Select`, `Input`, sonner toasts.

**Size:** about 330 changed lines without tests (server 90, functions 50, strings + errors 60, UI 130). One PR.

## Global constraints

- Czech UI text only in `src/lib/strings.ts`; code English.
- Every state change through `manage.ts` (audit in the same transaction). This PR writes no DB row itself.
- Every server function guarded and pinned in `tests/server-fn-guards.test.ts`.
- Screens import only `~/server/users/functions`.
- Never return a password hash to the client.

## Scope rulings (stated here so the judges can object)

1. **No deactivate / reactivate in the UI.** Spec §6 lists it, but Jakub's rule (2026-11-17): don't design for users becoming inactive. `updateUser` keeps `active`; the UI never sends it, and `updateUserFn` does not accept it.
2. **No passkey wipe.** Passkeys (PR #132) have not merged. Follow-up once they do.
3. **Admin's own row:** can rename self; role and reset password are not offered for self (a self-demotion locks the admin out of Správa mid-session; own password change belongs on Profil later). The server still enforces `last_admin`.
4. **Starting password (Jakub 2026-11-18):** 8 to 256 characters (`MIN_USER_PASSWORD = 8`; max = existing `MAX_PASSWORD_LENGTH`). Spec is silent on length; Jakub chose 8 (2026-11-18, decision card). Shown as plain text in the form (`type="text"`, `autoComplete="off"`), because the admin reads it out to the person; never echoed back after save.
5. **Login name** is trimmed and lower-cased before `createUser` (login already lower-cases), so "Starsi " becomes `starsi`. The existing regex `^[a-z][a-z0-9._-]{1,31}$` stays; no diacritics, the error says so.
6. **Login name cannot be changed** after creation (manage.ts has no such change; not in spec).
7. **Demo data:** the seeded family already covers this screen; no seed change.
8. **Drawer for the forms, Dialog only for the reset confirmation** (UI doc §5: forms go in the bottom sheet, which has `max-h-[85dvh]` and scrolls; Dialog only for what can't be undone). One screen, as UI doc §6 says for the admin.

## Review focus

1. Admin types a login name with capitals or a trailing space → saved lower-cased, trimmed; person logs in with it (Task 1 test).
2. Password exactly 7 / 8 / 256 / 257 characters → 7 and 257 refused with `invalid_password`, nothing written (Task 1 test).
3. A giver or taker calls the server functions → 403 from the guard; and the module itself refuses a non-admin actor with `not_admin`, nothing written (Task 1 test, guard test).
4. Reset password while that person is logged in → their sessions end, old password fails, new one works (Task 1 test).
5. Two admins, one demotes the other / admin tries to demote the last admin via a crafted call → `last_admin` with a Czech message (Task 1 test, Task 3 mapping).

### Task 1: Server module `src/server/users/admin.ts`

**Files:** create `src/server/users/admin.ts`, `src/server/users/admin.test.ts`; modify `src/server/users/index.ts` (exports).

**Interfaces (produces):**
```ts
export const MIN_USER_PASSWORD = 8
export type PeopleError = UserError | 'invalid_password'
export interface AddPersonInput { username: string; displayName: string; role: UserRole; password: string }
export interface EditPersonInput { displayName?: string; role?: UserRole }
export function addPerson(db: Db, adminId: number, input: AddPersonInput, now?: Date): Promise<Result<PersonSummary, PeopleError>>
export function editPerson(db: Db, adminId: number, userId: number, input: EditPersonInput, now?: Date): Result<PersonSummary, PeopleError>
export function resetPassword(db: Db, adminId: number, userId: number, password: string, now?: Date): Promise<Result<{ id: number }, PeopleError>>
```
Actor is always `{ kind: 'user', userId: adminId }`; `manage.ts` checks the actor is an active admin. Password checked (length) before hashing; hashing via `hashPassword` from `~/server/auth/password`. Map results to `PersonSummary` (id, username, displayName, role, active) — never the row.

### Task 4: Správa screen: add and edit drawers

**Files:** modify `src/routes/_app/sprava.tsx`; create `src/components/admin/PersonDrawer.tsx` (add and edit share one form), `src/components/admin/ResetPasswordDialog.tsx`, `src/components/admin/admin.test.tsx`.

**Layout (360 px):**
- Section label „Lidé“; the list card; under it the „Přidat člověka“ button (`size="lg"`, full width).
- Each row is a `<button>` (`min-h-tap`, full width, left aligned, `aria-label={cs.admin.editPerson(name)}`): avatar, then a column with display name (bold, `break-words`, wraps; 40 chars max) and login name under it (muted meta, `truncate`); role pill `shrink-0`, never cut; then a trailing `ChevronRight` (`aria-hidden`) as the tap cue. Own row adds „(ty)“ after the name.
- Tap → edit `Drawer`: name input, role `Select` (admin/giver/taker, labels from `cs.roles`), Uložit; below a divider the „Nastavit nové heslo“ button opening `ResetPasswordDialog` on top. Own row: no role select, no reset, `selfHint` line.
- Add `Drawer`: name, login name (hint), role (`Select`, default `taker`), password (hint `startPasswordHint(8)`), Uložit.
- Reset `Dialog`: password field with the same `startPasswordHint(8)`, `resetConfirm(name)` text, buttons Zrušit (closes the dialog only, back to the edit drawer) / Nastavit nové heslo. On success both close, toast, back on the list. It is the "ask first" step for the one action that cannot be undone (sessions end).
- Inputs: name inputs `maxLength={MAX_DISPLAY_NAME}`; login-name and both password inputs `type="text"`, `autoComplete="off"`, `autoCapitalize="none"`, `autoCorrect="off"`, `spellCheck={false}` (a phone keyboard must not change what the admin reads out); password inputs `maxLength={MAX_PASSWORD_LENGTH}`.

**States:** while a request runs the submit button is disabled and reads `cs.admin.saving`; a refusal shows `userErrorMessage` in a `role="alert"` line inside the drawer/dialog, the form keeps its values so the admin fixes and taps again; a thrown error shows `cs.login.failed` the same way. Success: toast (`added` / `saved` / `resetDone`), drawer closes, `router.invalidate()` reloads the list. Loader error: the app's existing route error screen (`cs.routeError`, retry). Empty state: none possible (the admin is always in the list), stated in a comment. All tap targets ≥ 44 px (`min-h-tap`, `size-tap`); no new animation besides `Dialog`'s (`motion-reduce:animate-none`) and the existing drawer's.
