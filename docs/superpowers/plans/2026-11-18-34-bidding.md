# Bidding on one-time tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (CLAUDE.md, PR flow step 3). Steps use checkbox (`- [ ]`) syntax for tracking.

**Issue:** [#34 Bidding on one-time tasks](https://github.com/SlatinskyJ/taskmaster/issues/34)

**Spec change alongside:** [#133 Spec: a bidder who says yes picks his or open for both](https://github.com/SlatinskyJ/taskmaster/pull/133) (Jakub's decision of 2026-11-18, one sentence in §5.2). This PR builds that sentence; it does not edit the spec.

**Goal:** A taker counters a giver's offer on a one-time task; the two sides go back and forth until one accepts, which reserves the task to that taker (or opens it on a tie), and everyone sees the whole thread.

**Architecture:** The rules already exist in `src/domain/bidding.ts` (#20); one of them gets stricter (a giver's accept also names who held the lowest bid he saw). This PR stores the negotiation as one append-mostly table, `task_thread` (the thread: giver-side offers and takers' bids), adds four server actions that load the rows, ask the domain and write the result with its audit entries in one transaction, and adds one screen, the task detail with the bid thread, for takers and givers.

**Tech Stack:** TanStack Start server functions, Drizzle + better-sqlite3 (sync transactions), Vitest, React 19, Tailwind v4 tokens, Czech strings in `src/lib/strings.ts`.

**Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-design.md` §5.2 (path 2 and Details, except "Changing the score of an agreed one-time task", which is #36), §3 (score agreement, [call] any active giver), §5.4 (release of a bid-agreed task: its new offer joins the thread), §5.10 (audit). UI doc `2026-11-16-taskmaster-ui-design.md` §7.1 TTask, §7.2 GBid, §2.2 (state "Vyjednává se"), §5 (steppers, no typing).

## What exists already

- `src/domain/bidding.ts`: `placeOneTimeBid`, `counterOneTimeOffer`, `acceptOneTimeOffer`, `acceptLowestBid` (all take `(task: OneTimeAgreement, people, actorId, score)` and return `Result<OneTimeAgreement, AgreementError>`); `src/domain/agreement.ts`: `OneTimeAgreement`, `liveBook`, `resolveOneTime`; `src/domain/lifecycle.ts`: `markAgreed(item, { takerId, giverId } | null)`. The only domain change is in Task 3: `acceptLowestBid` gets a fifth parameter, and `lowestBid` is exported.
- `src/server/tasks/tasks.ts`: `createTask`, `approveTaskOffer` (path 1), `reopenOffer` (release of a bid-won task), `resolveProposedTasks` (people-change hook). Today `agreementOf` passes the domain an empty bid book and takes the task's creator as the offering giver; this PR feeds it the real thread.
- `tasks` already has `offer_round`, `reserved_via` (`tap` | `bid`) and `reserved_giver_id`.

## Decisions this plan makes

1. **One table, `task_thread`, holds the negotiation.** It is not called "bids" because the giver side does not bid (`src/domain/bids.ts`); it offers. A row is a giver-side offer (`side = 'giver'`: the first offer, a counter, the re-offer after a release) or a taker's bid (`side = 'taker'`). A row is open until it closes as `replaced` (the same side put a new number), `accepted` (the task was agreed at it) or `closed` (the task was agreed at something else). While a task is `proposed` it has exactly one open giver row (the current offer; its `score` equals `tasks.score`, its `user_id` is the offering giver) and at most one open row per taker. Two partial unique indexes enforce both. Rows are never deleted, so every bid and counter stays in the history (spec §5.2).
2. **Audit actions.** A taker's bid: new `task.bid_placed`. A giver's counter: existing `task.score_countered`. A taker accepting the offer: existing `task.score_approved` then `task.agreed`. A giver accepting the lowest bid: new `task.bid_accepted` then `task.agreed`. All on entity `task`, so #36's task history gets them. `task.agreed` now always lists the thread rows it closed.
3. **An accepted bid starts a new offer round** (`offer_round + 1`, no approval rows in it): the agreed score is not the number the old round's approvals were given for, so none of them sits on it (spec §5.2 "pending score approvals are discarded").
4. **Screens.** One new route `/ukol/$taskId` for takers and givers (TTask and GBid are the same page with role-specific actions). Entry points: every "Čeká na tebe" row links to it, and a giver's Domů gets a "Nabídky" section (tasks with open bids) until #41 builds the full home. The spec lets a taker see the history in the "task detail and feed"; the UI doc has no feed screen, so the history is on the task page.
5. **"Others see the task as someone else's"** (issue, Done when): the other taker's task page shows `Rezervováno · Rezervoval <jméno>`, the thread with his own bid closed and no action buttons, and any action from a stale screen is refused. A list of other people's reservations on Domů is not added here (taker home is #40).
6. **One place writes a task's state.** `saveItem` (`src/server/tasks/item.ts`) is used by every lifecycle step and by every agreement. It closes the thread whenever a task leaves `proposed`, so a later step that does so (cancel, #36) cannot leave open offers or bids behind.
7. **One PR.** See Size.
8. **A bidder's yes picks** (Jakub, 2026-11-18, spec PR #133). A taker with an open bid gets two buttons: "Souhlasím" (path 1, `approveTaskOffer`: the task opens for every taker at the offer, his bid closes) and "Beru za <offer>" (`acceptOffer`: reserved to him). A taker without a bid gets "Souhlasím" only. The domain from #20 already allows both (`approveOneTimeOffer` takes a bidder, pinned by the domain test "a brother approving the plain offer while others bid opens it for everyone"), so this is screen work plus one server test.

## Global Constraints

- Scores are whole numbers from 1 (spec §3). No upper limit on the server; the stepper stops at 999 as the Nový úkol form does.
- Every state change writes its audit entry in the same transaction (`writeAudit(tx, …)`), and the check and the write share that transaction.
- An accept carries what the person saw and is refused when it changed (`offer_changed`): the offer for a taker; the lowest bid and who holds it for a giver.
- Czech text only in `src/lib/strings.ts`; code, DB and audit names in English.
- Stored instants are UTC via `toIsoUtc(now)`; tests use fixed instants, never `new Date()`.
- No import of React, TanStack, DB or Node into `src/domain/`.
- Never edit a committed migration; `drizzle/` generated files stay byte-identical to drizzle-kit's output (the data step is its own custom migration).
- Colours from theme tokens only, tap targets ≥ 44 px (`min-h-tap`), layout works at 360 px.
- Nobody becomes inactive part-way (Jakub, 2026-11-17): no new handling or tests for a deactivated bidder beyond the domain's existing live filter.

## Review Focus

Each line has its test in the task named.

1. A taker taps "Beru" on a stale screen after the giver gave the task to his brother → refused, nothing written, the reloaded page shows the brother's reservation (Task 3 "first agreement wins", Task 4 detail of a lost task).
2. The giver taps "Přijmout 22 (Mladší)" while the bids move → refused with `offer_changed` when the lowest score changed, when another taker now holds it, or when it became a tie; never a winner or a price he did not see (Task 3, domain and server).
3. A bid-won task is released and negotiated again → bids from the first negotiation must not count as open (Task 3 "released and negotiated again").
4. Tasks created before this migration have no thread rows → each gets its first offer by the data migration, or approving them would throw (Task 1).
5. A double tap sends the same bid twice → the second is `same_score`, one open bid remains; the unique index backs it (Task 1, Task 3).
6. A bidder taps "Souhlasím" → the task opens for everyone at the offer, not reserved to him; "Beru za 20" reserves it to him (Task 3 "a bidder's Souhlasím", Task 5 `bidActions`).

```ts
export const THREAD_SIDES = ['giver', 'taker'] as const
export const THREAD_CLOSINGS = ['replaced', 'accepted', 'closed'] as const

export const taskThread = sqliteTable(
  'task_thread',
  {
    id: integer('id').primaryKey({ autoIncrement: true }),
    taskId: integer('task_id').notNull().references(() => tasks.id),
    /** Who put the number: the offering giver, or the bidding taker. */
    userId: integer('user_id').notNull().references(() => users.id),
    side: text('side', { enum: THREAD_SIDES }).notNull(),
    score: integer('score').notNull(),
    createdAt: text('created_at').notNull(),
    /** Null while open. */
    closedAt: text('closed_at'),
    closedAs: text('closed_as', { enum: THREAD_CLOSINGS }),
  },
  (t) => [
    check('task_thread_side_check', sql`${t.side} IN ('giver', 'taker')`),
    check('task_thread_score_check', sql`${t.score} >= 1`),
    check(
      'task_thread_closed_check',
      sql`(${t.closedAt} IS NULL AND ${t.closedAs} IS NULL) OR (${t.closedAt} IS NOT NULL AND ${t.closedAs} IN ('replaced', 'accepted', 'closed'))`,
    ),
    uniqueIndex('task_thread_open_offer_idx').on(t.taskId).where(sql`closed_at IS NULL AND side = 'giver'`),
    uniqueIndex('task_thread_open_bid_idx').on(t.taskId, t.userId).where(sql`closed_at IS NULL AND side = 'taker'`),
    index('task_thread_task_idx').on(t.taskId),
  ],
)
export type ThreadRow = typeof taskThread.$inferSelect
```

- Consumes: `taskThread`, `ThreadRow` (Task 1).
- Produces, `thread.ts`:
  - `addEntry(tx: Tx, entry: { taskId: number; userId: number; side: 'giver' | 'taker'; score: number }, now: Date): { entry: ThreadRow; replaced: ThreadRow | null }` closes as `replaced` the open row it supersedes (giver side: the task's open offer; taker side: that taker's open bid), then inserts.
  - `openOffer(db: Db | Tx, taskId: number): ThreadRow` throws `task <id> proposed without an open offer` when there is none.
  - `openBids(db: Db | Tx, taskId: number): ThreadRow[]` open taker rows, by id.
  - `closeThread(tx: Tx, taskId: number, accepted: readonly number[], now: Date): number[]` closes every open row of the task, `accepted` for the ids given and `closed` for the rest; returns the ids it closed, ascending.
  - `threadOf(db: Db | Tx, taskId: number): ThreadRow[]` every row, by id.
- Produces, `item.ts`:
  - `toItem(row: TaskRow): Item`, `columnsOf(item: Item)` moved unchanged from `lifecycle.ts`, which imports them from `./item` and no longer exports `toItem` (nothing else imports it).
  - `saveItem(tx: Tx, before: TaskRow, item: Item, opts: { set?: { score?: number; agreedAt?: string | null; offerRound?: number }; accepted?: readonly number[] }, now: Date): { row: TaskRow; closed: number[] }` is the only code that writes a task's `status`, reservation and completion columns. It saves `columnsOf(item)`, `opts.set` and `updatedAt`. When `before.status` is `proposed` and `item.status` is not, it calls `closeThread(tx, before.id, opts.accepted ?? [], now)` and returns the ids as `closed`; otherwise `closed` is `[]`.
  - `runStep` (`lifecycle.ts`) saves through `saveItem(tx, row, next.value, {}, now)` and adds `closed` to its audit entry's `after`.
- Produces, `tasks.ts`:
  - `agreementOf(tx: Db | Tx, task: TaskRow): OneTimeAgreement` (now exported): for a proposed task `offer.proposedBy = openOffer(…).userId` and `book.bids = openBids(…)` as `{ by, score }`.
  - `type AgreedOneTime = Exclude<OneTimeAgreement, { status: 'proposed' }>`
  - `agree(tx: Tx, task: TaskRow, agreed: AgreedOneTime, accepted: readonly number[], actor: Actor, now: Date): TaskRow` replaces `openTask`. It calls `markAgreed(toItem(task), agreed.status === 'reserved' ? { takerId, giverId } : null)` (throws on an error: the caller checked `proposed`), saves it with `saveItem(tx, task, item, { set: { score: agreed.score, agreedAt, offerRound }, accepted }, now)` where `offerRound` is `task.offerRound + 1` when `agreed.score !== task.score`, and writes `task.agreed` with `before: { status, score, offerRound }` and `after: { status, score, offerRound, reservedBy, reservedVia, reservedGiverId, closed }` (`closed` from `saveItem`).
  - `createTask(db: Db | Tx, …)` (signature widened for the demo seed) adds the first offer with `addEntry`; `approveTaskOffer` and `resolveProposedTasks` end through `agree(tx, task, result, [openOffer(tx, task.id).id], actor, now)`; `reopenOffer` adds the giver's re-offer with `addEntry` and puts its `entryId` into its `task.score_approved` payload.
