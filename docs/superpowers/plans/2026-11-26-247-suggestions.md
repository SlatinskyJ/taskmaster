**Goal:** Store suggestions, let the admin mark them done or dismissed, and send one to GitHub as an issue: the server half of [#247 Suggest app improvements from Profil](https://github.com/SlatinskyJ/taskmaster/issues/247), behind a new `suggestions` switch.

**Architecture:** Stacked PRs, like descriptions (#252 server, #260 screens). **This PR (A):** table + migration + switch, the text and state rules in `src/domain/suggestions.ts`, the store in `src/server/suggestions/` (writes through `writeAudit` in one transaction), a tiny GitHub client with injected `fetch`, and the server functions. **PR B (own plan, stacked on this one, `Closes #247`):** Profil form and my list, Správa list with Hotovo / Zamítnout / Poslat na GitHub preview, Czech strings, demo piece and seed, e2e + keyboard case. No screen in this PR, so no `preview` label.

**Size:** about 380 changed lines (not counting tests, migrations and generated files). The screens are a separate stacked PR to stay under 400.

**Tech Stack:** TanStack Start server functions, Drizzle + SQLite, Vitest. Node 22 global `fetch` (no new dependency).

**Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-design.md` §5.13 (and §5.10 audit list).

## Global Constraints

- §5.13: anyone signed in (taker, giver, admin) suggests. Title required, 1–120 characters; description up to 2,000, may be empty.
- States: `new` → `sent` or `dismissed`; `new` or `sent` → `done`. Done and dismissed are final. Only the admin changes a state. Never deleted.
- Send: preview filled **without the author's name**, admin may edit title and body; the suggestion's own text stays as written; the sent text and issue link are stored; at most once; GitHub failure → nothing changes, error, retry possible. Issue gets **no label**.
- Token: runtime env secret, never committed; fine-grained, this repo only, *Issues: read and write*. Without it the send is unavailable, everything else works.
- Switch `suggestions`, off in prod (migration seeds it off). With it off every server function returns `feature_off` and writes nothing.
- Every write and its audit entry in one transaction (`writeAudit`). Entries: `suggestion.created`, `suggestion.sent` (with issue URL + sent text), `suggestion.done`, `suggestion.dismissed`.
- Code, identifiers, logs in English. No Czech text in this PR (screens are PR B).

## Rulings (mine, for the brief)

1. **Text cleaning** is its own step in `src/domain/suggestions.ts`; `description.ts` is not touched (descriptions keep their rule). Line breaks to LF; removed: the description rule's set (C0 controls except TAB/LF, DEL, bidi embeddings/overrides/isolates) **plus** zero-width and direction marks U+200B–U+200F, U+2060 and U+FEFF; then trimmed. The title is one line: line breaks and tabs become a space. Empty description is stored as `NULL`. Limits count **characters (code points)**, `[...text].length`, the same unit as SQLite `length()` in the checks.
2. **Issue limits:** issue title 1–120 (same as a suggestion), issue body up to 4,000 (the admin may add context). The server appends one fixed line to the body, `_Suggested in the Taskmaster app._`, so a reader knows where it came from; it holds no name.
3. **Repository** is a constant, `SlatinskyJ/taskmaster` (spec: "the app's own repository"); only the token is configured, env `SUGGESTIONS_GITHUB_TOKEN`.
4. **Double send:** one process serves the app, so an in-process claim per suggestion id (`claimSend` / `releaseSend` / `isSending` in `./sending.ts`) blocks a second send and a close of the same id while GitHub answers (`busy`). The DB update also requires `status = 'new'`.
7. **Issue made, not saved:** if GitHub created the issue but the DB update changes no row or the transaction throws, nothing is stored (spec: nothing changes), the result is `sent_not_saved` with the issue's `url`, and `console.error` logs the suggestion id, issue number and url. PR B shows that link and tells the admin not to send again (mark it done instead), so a retry never opens a second public issue unknowingly. This is SQLite failing mid-request, so very rare.
8. **No per-user limit** on creating: signed-in family members only, and rows are small; the raw input is capped in `parse.ts` (10,000 characters per field) before cleaning.
5. **Audit of a failed send:** none (spec: "nothing changes"). The error is logged without the token or response body.
6. **Lists:** newest first by `created_at`, then `id`. The admin list carries the author's display name; my list never carries an author.

## Review Focus

1. A title of only spaces, line breaks or hidden characters → refused `title_empty`, nothing stored. (Task 2 tests.)
2. A double tap on send → exactly one GitHub call; the second call gets `busy`. (Task 5 test.)
3. GitHub answers 401 / 422 / 500, times out, or returns an unexpected `html_url` → `github_failed`, row still `new`, no audit entry, token absent from the thrown/logged text. (Task 4 and 5 tests.)
4. A taker or giver calls an admin function → refused by the guard; `listMySuggestionsFn` returns only the caller's rows. (Task 6 guard test, Task 3 test.)
5. Dismissing a sent suggestion, or any change to a done/dismissed one, or a sent one back to new → refused (`not_new` / `closed`), also by the DB checks and triggers. (Task 1, 2 and 3 tests.)
