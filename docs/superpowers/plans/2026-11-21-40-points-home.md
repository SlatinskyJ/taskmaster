# Points query and taker home (Domů) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Issue:** [#40 Points query and taker home (Domů)](https://github.com/SlatinskyJ/taskmaster/issues/40)

**Goal:** a taker opens Domů and sees his points card (confirmed vs pending vs the two levels, and how many points he still needs) above "Čeká na tebe", his reservations and the open tasks, and can mark an open task Hotovo without reserving it first.

**Architecture:** a read-only points module `src/server/points/` turns the taker's confirmed tasks into domain ledger entries and takes the running total from the domain's `runningTotal` (`src/domain/settlement.ts`), so later issues only add their own entries; pending is summed from done, unconfirmed tasks. One GET server function serves it (a taker gets only his own row, a giver every taker's row). Domů's loader calls it and renders the existing `PointsBar` (#32) in a card. No schema change, no migration, no state change.

**Tech Stack:** TanStack Start server functions, Drizzle/SQLite, React, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-design.md` §5.5, §5.7, §5.9 (running total), §7 (home sketch); UI doc `docs/superpowers/specs/2026-11-16-taskmaster-ui-design.md` §3, §4, §6, §7.1, mockup Main.

**Size:** about 220 changed lines outside tests (points module ~70, server function ~25, Domů route ~20, MyPoints ~50, TakerBoard/WorkButtons ~40, strings ~8, demo seed ~25).

## Global Constraints

- Czech UI text only in `src/lib/strings.ts`; code in English.
- `src/domain/` stays framework-free.
- Spec §5.7: confirmed = "the running total: carry-over + confirmed this period"; pending = done, unconfirmed, shown separately; both against lower and upper. "Givers see the same for every taker." A taker sees his own.
- Levels until periods exist: lower 50, upper 100. **Jakub, 2026-11-21 20:24 (project chat):** no in-app week settings for week 1; the periods work ships the spec defaults "7 days, cutoff Sunday, lower 50, upper 100". The spec §5.8 names no numbers, so this ruling is the source of 50/100.
- Recurring chores are hidden for launch (Jakub 2026-11-21, separate ad-hoc PR); only one-time tasks earn points here.
- Tap targets ≥ 44 px (`min-h-tap`, `size-tap`); animations have a `motion-reduce:` opt-out (or sit behind `useEffectsEnabled`).

## Decisions (rulings for the brief)

1. **Running total through the domain.** `takerPoints` builds `LedgerEntry[]` (`{ kind: 'completion', takerId, points }` per confirmed task with an earner) and takes `confirmed` from `runningTotal(entries, takerId)`. No settlement or adjustment rows exist yet, so today it equals the sum of confirmed scores. Owners of the rest, named in the module header and as a comment on each issue: [#44 Weekly meeting](https://github.com/SlatinskyJ/taskmaster/issues/44) adds `settlement` entries (points deducted), [#48](https://github.com/SlatinskyJ/taskmaster/issues/48) adds `adjustment` entries, [#42 Periods](https://github.com/SlatinskyJ/taskmaster/issues/42) switches `levels` to the current period (agreed with the #42 thread; it keeps the `DEFAULT_LEVELS` name).
2. **Points card above "Čeká na tebe".** UI doc §6 [call] says "Čeká na tebe" is always at the top of Domů, and the spec §7 sketch and mockup Main put the points in the header, above it. The card is part of the header (greeting + points), so "Čeká na tebe" stays the first list.
3. **Volné rows get Hotovo + Rezervovat.** Spec §5.5 lets a taker mark an open task done without reserving it, and the sketch shows `[Hotovo]` on open rows. Hotovo keeps its label (main action); Rezervovat becomes a 44 px icon button (`Bookmark`, `aria-label` and `title` = "Rezervovat"), the same pattern as Uvolnit on "Moje" rows (#148), so a long name and chip read at 360 px. The task page keeps the labelled Rezervovat for anyone unsure.
4. **"Still missing" line without the meeting time.** Mockup Main's line "Do spodní hranice chybí 5 b. Schůzka v neděli 18:00." is built without its second sentence: the meeting time comes from the current period (#42).
5. **"+N" float on the points card.** The row moves from Volné to Moje on reload, so the float sits on the points card: when this taker's pending goes up the card shows "+N" in the pending colour, when confirmed goes up (a task without approval, or a giver approved) "+N" in green. The first render and a change of taker never float.
6. **No "+ Zapsat udělanou práci" button.** It opens self-logging of a recurring chore (spec §5.3), which is hidden for launch; it comes back with recurring chores.
7. **Admin** has no Domů (existing guard) and the server function refuses him. Givers' Domů is unchanged here; #41 adds their points.

## Review Focus

1. A task a **giver** completed (`earner_id` null, status confirmed) counts for nobody: Task 1.
2. A taker with **no tasks** sees `0 ✔ + 0 ⏳` and "Do spodní hranice chybí 50 bodů.": Tasks 1 and 3.
3. **Open / reserved / proposed / cancelled** tasks never add points; a rejected completion leaves pending: Task 1.
4. A taker never receives his brother's numbers from the server function: Task 2 (through the handler).
5. Hotovo or Rezervovat on an open row while another tap is busy is disabled (shared busy state): Task 3.
