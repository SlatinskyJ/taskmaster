# Install the app from Profil Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A section *Aplikace* on Profil with a button *Nainstalovat aplikaci*: the browser's install prompt on Chrome/Edge/Android, three short steps on iPhone/iPad, hidden when the app already runs from the home screen or the browser cannot install.

**Architecture:** A framework-free module `src/pwa/install.ts` decides the mode from plain inputs and holds the captured `beforeinstallprompt` event in a tiny store. An inline boot script in `<head>` catches the event before React hydrates (it can fire before Profil is ever opened). A Profil component reads the store with `useSyncExternalStore` (server snapshot: hidden, so no hydration mismatch) and shows the button or the iOS sheet.

**Tech Stack:** TanStack Start, React 19, vaul `Drawer`, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-design.md` §11 (PWA [call]); issue [#302 Install the app from Profil](https://github.com/SlatinskyJ/taskmaster/issues/302).

**Size:** about 170 changed lines outside tests (install.ts ~80, ProfileInstall.tsx ~70, strings ~10, root + profil + suites ~6, spec 1). One PR.

## Pre-flight (pr-review-rounds §1)

- No state change, no audit, no server function, no role: those Tests items don't apply. Real entry point: the e2e runs the boot script and the Profil route as shipped.
- Tap targets: the row button and *Rozumím* are `min-h-tap`, full width.
- Motion: only the vaul `Drawer`, which already has its `motion-reduce:` opt-out; nothing new animates.
- Busy state: while the browser's prompt is open (`install()` pending) the row button is `disabled`. The prompt can't fail with a server error; if `prompt()` throws, the event is dropped and the section hides (no dead button), logged with `console.warn('[pwa] install prompt failed', error)`.
- No loader, no irreversible action.
- 360 px: label *Nainstalovat aplikaci* and the hint wrap under the icon column; nothing is cut. Steps in the sheet wrap.

## Review Focus

1. `beforeinstallprompt` fires before hydration (fast connection, Profil not open): the button must still work later. → boot script + e2e "event before load".
2. iPadOS 13+ reports a Mac user agent: must get the iOS steps, not "hidden". → unit test `Macintosh` + `maxTouchPoints 5` → `ios`.
3. User dismisses the native prompt: the event is single-use, so the button must disappear until the browser fires a new one (no dead button). → unit test + e2e.
4. Already installed on iOS (`navigator.standalone === true`) or Android (`display-mode: standalone`): no section. → unit tests + e2e.
5. Desktop Firefox / Safari on Mac (no event, not iOS): no section. → unit test + e2e "no event".

### Task 1: Install mode and prompt store

**Files:**
- Create: `src/pwa/install.ts`
- Test: `src/pwa/install.test.ts`

**Interfaces:**
- Produces:
  - `type InstallMode = 'hidden' | 'prompt' | 'ios'`
  - `interface InstallEnv { standalone: boolean; userAgent: string; maxTouchPoints: number; hasPrompt: boolean }`
  - `installMode(env: InstallEnv): InstallMode` — `standalone` → hidden; else `hasPrompt` → prompt; else iOS (`/iPhone|iPad|iPod/` in UA, or `Macintosh` with `maxTouchPoints > 1`) → ios; else hidden.
  - `readInstallEnv(win: Window, hasPrompt: boolean): InstallEnv` — `standalone` = `matchMedia('(display-mode: standalone)').matches || navigator.standalone === true`.
  - `interface PromptEvent extends Event { prompt(): Promise<void>; userChoice: Promise<{ outcome: 'accepted' | 'dismissed' }> }`
  - `const BOOT_KEY = '__tmInstallPrompt'` and `installBootScript: string` — inline JS: on `beforeinstallprompt`, `preventDefault()` and save the event as `window[BOOT_KEY]`; on `appinstalled`, set `window[BOOT_KEY] = 'installed'`.
  - `createInstallStore(win: Window): { subscribe(cb: () => void): () => void; getSnapshot(): InstallMode; install(): Promise<void> }` — starts from `win[BOOT_KEY]`, keeps listening to both events itself, recomputes the snapshot on each (cache it: `useSyncExternalStore` needs a stable value). `install()` calls `prompt()`, awaits `userChoice`, then drops the event whatever the outcome (it is single-use) and notifies; a throw from `prompt()` also drops it (warn, no rethrow). `install()` with no event does nothing. After `appinstalled` the mode is hidden.
  - `getInstallStore(): ReturnType<typeof createInstallStore>` — lazy singleton for `window`.

- [ ] **Step 1: Write the failing tests** (`describe('installMode')`, `describe('createInstallStore')`, fake `Window` from an `EventTarget` + stubbed `matchMedia`/`navigator`)
  - `installMode({standalone:true, hasPrompt:true, ...iphone})` → `'hidden'`
  - Chrome Android UA, `hasPrompt:true` → `'prompt'`; same UA `hasPrompt:false` → `'hidden'`
  - iPhone Safari UA → `'ios'`; iPhone CriOS UA → `'ios'`
  - `Macintosh` UA + `maxTouchPoints: 5` → `'ios'`; `Macintosh` + `0` → `'hidden'`
  - Firefox Windows UA → `'hidden'`
  - store: boot key holds an event → snapshot `'prompt'`; later `beforeinstallprompt` dispatched → `'prompt'` and subscriber called; `install()` calls `prompt()` once and after `userChoice` resolves `'dismissed'` the snapshot is `'hidden'`; `appinstalled` → `'hidden'`; boot key `'installed'` → `'hidden'`; `prompt()` rejects → `install()` resolves and snapshot `'hidden'`; `install()` with no event resolves without calling anything; two `getSnapshot()` calls with no event in between return the same value.
  - boot script: `new Function('window', installBootScript)` run against the fake window, dispatch the event → `window[BOOT_KEY]` is it and `preventDefault` was called.
