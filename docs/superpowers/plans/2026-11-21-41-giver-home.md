# Giver home and task list Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A giver's Domů shows every taker's points this week next to what waits for them (GHome), and Úkoly lists all one-time tasks grouped by state (GTasks). Closes #41.

**Architecture:** Reuses #40's `getPointsFn` (a giver already gets every taker's row) and the existing `ToApprove` / `BidsToAnswer` lists. A new `TakersPoints` card renders one quiet `PointsBar` per taker. Úkoly groups the existing `listTasksFn` result with a pure `groupTasks` helper. The tap-point "+N" float from #40 moves into a small shared `TapFloat` so ToApprove's ✓ Schválit can show the green "+N" (UI doc §4 "Confirmed") and the task page's Hotovo shows its pending "+N" too.

**Tech Stack:** TanStack Start, React, Tailwind, Vitest (static render with mocked modules), Playwright e2e on the built server.

**Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-design.md` (§5.5, §5.7, §7) and `docs/superpowers/specs/2026-11-16-taskmaster-ui-design.md` (§3, §4, §6, §7.2 GHome, GTasks, §8).

**Stacked on:** #40 (PR #162, branch `40-points-home`). This PR's base is `40-points-home`.

## Global Constraints

- Czech UI text only in `src/lib/strings.ts`; code in English.
- Givers see every taker's points (spec §5.7); takers only their own (already enforced by `pointsView`, #40).
- Levels: `points.levels` from `getPointsFn` (lower 50, upper 100 until #42 lands). Never hard-code 50/100 in components.
- "Čeká na tebe" stays at the top of Domů (UI doc §6 [call]).
- Effects (confetti, "+N") off with reduced motion or the profile's Efekty switch (`FloatingPoints` already handles this).
- Recurring chores are hidden for launch (PR #163, `FEATURES.recurring`): no "+ Teď" on Úkoly here; instances and "+ Teď" belong to #38.
- Layout works from 360 px.
- No new state changes, so no audit entries; no schema change.

## Scope decisions

- **GHome sections, in order:** "Čeká na tebe" → "Kluci tento týden" (points card) → "Ke schválení" (ToApprove) → "Vyjednávání" (BidsToAnswer). This follows mockup GHome. The meeting card from the mockup is #44's; the period/week picker is #42's.
- **"Week at a glance"** (UI doc §7.2) = the points card: each taker's confirmed + pending this week against the levels. Nothing more until periods (#42) exist.
- **Points card:** one row per taker: name, then `PointsBar` with `celebrate` off (UI doc: celebrations only on the taker's own bar) and `subject={String(id)}`. One line under all bars: `Hranice: spodní 50 · horní 100`. No takers → the card is not rendered.
- **GTasks groups, in order:** Návrh (proposed, incl. negotiating), Volné (open), Rezervováno (reserved), Čeká na potvrzení (done_unconfirmed), Hotovo (confirmed), Zrušeno (cancelled). Active states first, finished ones last. Each group: a section label with count, then the rows as today. Empty groups are not shown. Inside a group keep `listTasks` order (newest first). No list at all → the existing empty state.
- **Conflicts with PR #163** (hide recurring): both touch `src/routes/_app/index.tsx` and `src/routes/_app/ukoly/index.tsx`. To keep the merge small: the giver branch of Domů becomes one `<GiverHome …/>` component; Úkoly's one-time section becomes one `<TaskGroups …/>` call. Whichever PR lands second rebases and keeps both (the `FEATURES` switches stay as #163 has them).

## Review Focus

1. A giver with zero takers in the family (fresh install): Domů must not show an empty "Kluci tento týden" card.
2. A taker hitting the giver's Domů code path: must still get only his own card (#40 behaviour) and no "Kluci" card.
3. A long Úkoly list with every state: finished groups stay below all active ones; a cancelled task never sits between active groups.
4. Approving on Domů while scrolled: the green "+N" appears at the tapped ✓, not off-screen.
5. Efekty off: no "+N" anywhere (approve or Hotovo on the task page).
