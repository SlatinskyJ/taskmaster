# Giver home and task list Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A giver's Domů shows every taker's points this week, the offers still waiting for the boys, and what waits for the giver (GHome); Úkoly lists all one-time tasks grouped by state (GTasks). Closes #41.

**Architecture:** Reuses #40's `getPointsFn` (a giver already gets every taker's row), `listTasksFn` and the existing `ToApprove` / `BidsToAnswer` lists. A new `TakersPoints` card renders one quiet `PointsBar` per taker. Úkoly groups `listTasksFn` with a pure `groupTasks`. The tap-point "+N" float from #40 moves out of the component that tapped into one app-wide `FloatLayer` (mounted in the `_app` layout, fed by a tiny store), so it survives the reload that unmounts the tapped row, section or panel. That gives ✓ Schválit its green "+N" (UI doc §4 "Confirmed") and the task page's Hotovo its pending "+N".

**Tech Stack:** TanStack Start, React (`useSyncExternalStore`), Tailwind, Vitest (static render with mocked modules), Playwright e2e on the built server.

**Spec:** `docs/superpowers/specs/2026-11-16-taskmaster-design.md` (§5.2, §5.5, §5.7, §7) and `docs/superpowers/specs/2026-11-16-taskmaster-ui-design.md` (§3, §4, §6, §7.2 GHome, GTasks, §8).

**Stacked on:** #40 (PR #162, branch `40-points-home`). This PR's base is `40-points-home`.

## Global Constraints

- Czech UI text only in `src/lib/strings.ts`; code in English.
- Givers see every taker's points (spec §5.7); takers only their own (`pointsView`, #40).
- Levels: `points.levels` from `getPointsFn` (lower 50, upper 100 until #42 lands). Never hard-code 50/100 in components.
- "Čeká na tebe" stays at the top of Domů (UI doc §6 [call]).
- Effects ("+N", confetti) off with reduced motion or the profile's Efekty switch (`FloatingPoints` / `useEffectsEnabled`).
- Recurring chores are hidden for launch (PR #163, `FEATURES.recurring`): no "+ Teď" on Úkoly here; instances and "+ Teď" belong to #38.
- Layout works from 360 px.
- No new state changes, so no audit entries; no schema change; no new server function.

## Scope decisions

- **GHome sections, in order:** "Čeká na tebe" → "Kluci tento týden" (points card) → "Ke schválení" (ToApprove) → "Vyjednávání" (BidsToAnswer) → "Čeká na kluky" (new). This follows mockup GHome. The meeting card from the mockup is #44's; the period/week picker is #42's.
- **"Week at a glance"** (UI doc §7.2) = the points card. Nothing more until periods (#42) exist.
- **Points card:** one row per taker in id order: `Avatar` (size `sm`) and name, then `PointsBar` with `celebrate` off (celebrations only on the taker's own bar) and `subject={String(id)}`, levels from `points.levels`. The bars already print "spodní / horní" under their ticks, so no extra levels line. No takers → not rendered.
- **"Čeká na kluky" (issue scope "approvals waiting", mockup "Schválili … · chybí …"):** proposed tasks with no bids whose offer still waits only for takers (the giver viewing is not in `waitingFor`). Row: title, chip, score, meta = `waitingText(task, me)` ("Čeká se na: Starší nebo Mladší"), action = the existing Otevřít link to `/ukol/$taskId`. Tasks with bids are in Vyjednávání; tasks waiting for this giver are in Čeká na tebe. Empty → not rendered. Data: the giver loader adds `tasks: await listTasksFn()` (giver-only, already guarded); a pure `waitingOnTakers(list, me)` filters.
- **GTasks groups, in order:** "Návrhy a vyjednávání" (proposed, incl. negotiating), Volné (open), Rezervováno (reserved), Čeká na potvrzení (done_unconfirmed), Hotovo (confirmed), Zrušeno (cancelled). Active states first, finished ones last. Each group: a section label with count, then the rows as today. Empty groups are not shown. Inside a group keep `listTasks` order (newest first). No list at all → the existing empty state. In the Návrh group the meta line for a task waiting for the boys becomes `waitingText` (replacing the plain `cs.tasks.waitingForTaker`).
- **Conflicts with PR #163** (hide recurring): both touch `src/routes/_app/index.tsx` and `src/routes/_app/ukoly/index.tsx`. To keep the merge small: the giver branch of Domů becomes one `<GiverHome …/>`; Úkoly's one-time section becomes one `<TaskGroups …/>`. Whichever PR lands second merges and keeps both (the `FEATURES` switches stay as #163 has them; with recurring off #163 hides the "Jednorázové" label, so the group labels are the only labels on Úkoly).
- **Taker card gating:** Domů renders `MyPoints` only for `user.role === 'taker'`, now that the giver loader also returns `points`.

## Review Focus

1. A giver with zero takers (fresh install): no empty "Kluci tento týden" card.
2. A taker on Domů: only his own card, no "Kluci" card, no "Čeká na kluky".
3. Úkoly with every state: finished groups below all active ones; a new status in `TASK_STATUSES` cannot silently drop out (exhaustive map).
4. Approving the last waiting completion, or Hotovo on the task page: the "+N" still shows although the tapped section/panel unmounts on reload.
5. Efekty off: no "+N" anywhere.
