# Live changes, PR 1: server hub and stream — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server side of the live change banner (#299): every committed change becomes one event,
mapped to topics, delivered over SSE to the open streams whose signed subscription matches, with
catch-up from the audit log. No screen subscribes yet and nothing is visible; PR 2 adds screens'
topics, the Czech texts and the banner.

**Architecture:** `writeAudit` notifies a listener; the live hub flushes committed audit rows in a
microtask (better-sqlite3 transactions are synchronous, so by then a transaction has committed or
rolled back and rolled-back rows simply don't exist). Rows are grouped into changes by a new
nullable `change_id` column, mapped to topics by one pure function plus small DB lookups, and
written to matching streams. Subscriptions are HMAC-signed by the server with the session token
as key, so a stream can only carry topics the user's own data functions issued.

**Tech Stack:** TanStack Start server route (`src/routes/api/live.ts`) returning a
`ReadableStream` `text/event-stream`, Drizzle + better-sqlite3, `node:crypto` HMAC-SHA256, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-26-live-changes-design.md` (main spec §2, §5.12, §7,
§11 on the spec PR #300, which this PR is stacked on).

**Size:** about 450 changed lines without tests and the migration; over 400 because the hub, the
stream and the mapping only work together (a hub with no stream can't be tested end to end, a
mapping with no hub ships dead code). PR 2 (screens + banner + texts) and possibly PR 3 (the
remaining screens) stack on it.

## Global Constraints

- Code, identifiers, logs in English; no Czech text in this PR (texts arrive in PR 2).
- Every state change already writes its audit entry; this PR adds **no** new state change and no
  new audit action. It reads the audit log, never writes to it beyond the new column.
- `src/server/audit/` stays free of HTTP and live imports: it exposes a listener hook only.
- The audit table is append-only (DB triggers). The migration only `ALTER TABLE ... ADD COLUMN`;
  it must not make drizzle-kit rebuild the table (schema WARNING in `src/server/db/schema/audit.ts`).
- Launch switch `liveChanges`, off in production (migration seeds 0); the `demo` seed turns it on.
  Off: the stream endpoint answers 404 and `liveSubscription` returns `null`.
- Production is HTTPS only; nothing here may need a WebSocket or a proxy change. Heartbeat
  **25 s** (Apache `ProxyTimeout 60`).
- Limits: `TOPIC_LIMIT = 20` topics per stream; `STREAMS_PER_SESSION = 3`, a 4th closes the oldest.
- Out of scope topics: launch switch flips (`feature.switched`) and passkeys (`passkey.*`), plus
  `auth.*`: they map to no topics.
- An event never carries `before` / `after` (audit README rule). Wire payload is exactly
  `LiveEvent` below.

## Review Focus

1. **A rolled-back change emits nothing.** A `withAudit` whose change throws after `writeAudit`
   ran must send no event. → test in Task 3.
2. **A boy never gets a slice he can't load.** A subscription token signed for user A replayed
   with user B's session, or with an edited topic list, is refused (401). → tests in Task 4.
3. **Reconnect after sleep replays exactly the missed changes**, grouped, nothing twice: events
   with id ≤ `Last-Event-ID` are not resent; a change split across the replay/live boundary is
   sent once. → tests in Task 5.
4. **The same tab's own change is not echoed**, but the same user's other tab gets it. → Task 3.
5. **Logout or an expired session ends the stream** at the next heartbeat instead of streaming
   forever. → Task 5.

### Task 2: topics and the audit → topics mapping

**Files:**
- Create: `src/server/live/topics.ts`, `src/server/live/mapping.ts`
- Test: `src/server/live/mapping.test.ts`

**Interfaces:**
- Produces (`topics.ts`):
  ```ts
  export type Topic =
    | 'tasks' | `task:${number}`
    | 'templates' | 'templates:proposed' | `template:${number}`
    | 'week' | 'proposals' | 'settings' | 'people'
    | `points:${number}`              // a taker's totals, by user id
    | 'disputes' | `disputes:about:${number}` | 'disputes:about:none' | `disputes:by:${number}`
    | 'suggestions' | `suggestions:by:${number}`
  export const TOPIC_LIMIT = 20
  export function isTopic(s: string): s is Topic
  ```
  Rule (comment at the top of `topics.ts`): a broad topic (`disputes`, `suggestions`,
  `templates:proposed`) is only for viewers who may load every row of it; a viewer who may load
  a slice gets the slice topics. A change fires the broad topic and every slice it belongs to.
- Produces (`mapping.ts`):
  `topicsOf(db: Db, row: AuditLogRow): Topic[]` (deduplicated, `[]` for out of scope actions).

Mapping (the contract the tests pin):

| Action prefix / entity | Topics |
|---|---|
| `task.*`, `instance.*` on task `id` | `task:<id>`, `tasks`, `week`; `points:<u>` for every user id in the row's `reservedBy`, `completedBy`, `earnerId` now and the `reservedBy` / `earnerId` keys of `before` / `after` JSON; `template:<templateId>` if the row has one |
| `template.*` on `id` | `template:<id>`, `templates:proposed` if status (now or `before.status`) is `proposed`, else `templates`; `tasks` for `template.agreed`, `template.cancelled` |
| `period.created`, `period.ended` | `week`, `proposals`, `tasks` |
| `period.proposal_*`, `defaults.proposal_*` | `proposals`, `week` |
| `settlement.*` on `id` | `week`, `points:<settlement.takerId>` |
| `points.adjusted` on `id` | `week`, `points:<adjustment.takerId>` |
| `dispute.*` on `id` | `disputes`, `disputes:by:<openedBy>`, `disputes:about:<takerId>` or `disputes:about:none` (takerId via `loadTarget` in `src/server/disputes/targets.ts`); `dispute.corrected` adds the corrected taker's `points:<id>` and `week` |
| `user.created`, `user.updated` | `people` |
| `settings.changed` | `settings`, `week` |
| `suggestion.*` on `id` | `suggestions`, `suggestions:by:<authorId>` |
| `auth.*`, `passkey.*`, `feature.switched` | none |
| entity `app_meta`, `session` | none |

### Task 3: the hub

**Files:**
- Create: `src/server/live/hub.ts`, `src/server/live/index.ts`
- Test: `src/server/live/hub.test.ts`

**Interfaces:**
- Consumes: `onAuditWritten` (Task 1), `topicsOf` (Task 2).
- Produces:
  ```ts
  export interface LiveEvent {
    id: number            // the newest audit id in the change (SSE event id)
    change: number        // change_id ?? id of its first entry
    action: AuditAction   // of the change's first entry (its main entry)
    entityType: EntityType
    entityId: string
    actor: { kind: 'user'; userId: number } | { kind: 'system' }
    at: string
  }
  export interface Stream { sessionId: number; userId: number; tab: string; topics: ReadonlySet<Topic>; send(e: LiveEvent): void; close(): void }
  export function createHub(db: Db, opts?: { originTab?: () => string | undefined }): Hub
  interface Hub {
    attach(s: Stream): () => void          // enforces STREAMS_PER_SESSION = 3: closes the oldest of that session
    changesSince(afterId: number, topics: ReadonlySet<Topic>): LiveEvent[]   // catch-up, grouped
    stop(): void
  }
  export function liveHub(): Hub           // the app's one hub, created lazily with getDb()
  ```
  `originTab` defaults to reading the `x-tm-tab` request header (`getRequestHeader` from
  `@tanstack/react-start/server`, wrapped in try/catch: outside a request, e.g. the scheduler,
  it is `undefined`).

Behaviour:
- On the first `onAuditWritten` call of a synchronous run, record `originTab()` and
  `queueMicrotask(flush)`. `flush` selects `audit_log` rows with `id > lastSent` ordered by id
  (`lastSent` starts at `max(id)` when the hub is created), groups them by change key, builds one
  `LiveEvent` per change with the union of its rows' topics, and sends it to every attached
  stream with a shared topic **and** `stream.tab !== origin tab`.
- A change whose rows straddle two flushes can't happen (one transaction, one synchronous run);
  `changesSince` groups the same way and only returns changes whose newest id is `> afterId`.

- [ ] **Step 1: failing tests** (fake streams collecting `send` calls; `createTestDb()`):
  - `a committed change reaches a stream with a matching topic once`
  - `a stream without a shared topic gets nothing`
  - `a rolled-back withAudit sends nothing` (change throws after a `writeAudit` in a nested `db.transaction`)
  - `settlement with two taker entries is one event; id is the newest entry id; action is the first entry's`
  - `the origin tab is skipped; another tab of the same user gets it`
  - `scheduler change (no request, actor system) reaches everyone matching`
  - `a fourth stream of one session closes the oldest; another session's streams are untouched`
  - `changesSince(5, topics) returns changes with newest id > 5 that match, grouped, oldest first`
- [ ] **Step 2:** FAIL. **Step 3:** implement. **Step 4:** PASS, `pnpm lint`.

### Task 4: signed subscriptions

**Files:**
- Create: `src/server/live/subscription.ts`
- Test: `src/server/live/subscription.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export interface LiveSub { token: string; asOf: number }   // what a data function returns
  export function signSubscription(key: string, userId: number, topics: readonly Topic[], asOf: number): string
  export function readSubscription(key: string, token: string): { userId: number; topics: Topic[]; asOf: number } | null
  export function liveSubscription(user: CurrentUser, topics: readonly Topic[]): LiveSub | null
  ```
  Token = `base64url(JSON {u, t, a}) + '.' + base64url(HMAC-SHA256(key, payload))`, compared with
  `timingSafeEqual`. `liveSubscription` uses `sessionToken()` (`~/server/auth/http`) as the key and
  `max(audit_log.id)` as `asOf`; it returns `null` when `liveChanges` is off or there is no session
  token. PR 2's data functions call it; this PR calls it only from tests.

### Task 5: the stream endpoint and the tab header

**Files:**
- Create: `src/routes/api/live.ts` (server route, `GET`)
- Create: `src/server/live/stream.ts` (framework-light core: `openStream(req: StreamRequest, deps): Response`)
- Modify: `src/start.ts` (function middleware adds `x-tm-tab`), create `src/lib/tab.ts`
  (`tabId(): string`, one `crypto.randomUUID()` per page load, kept in module memory)
- Modify: `src/routeTree.gen.ts` (generated)
- Test: `src/server/live/stream.test.ts`

**Interfaces:**
- Request: `GET /api/live?t=<token>&t=<token>…&since=<asOf>&tab=<tabId>` (+ `tmFrame` in viewer
  frames, read by the existing frame code). Header `Last-Event-ID`, when present, wins over `since`.
- Responses: `404` when `liveChanges` is off; `401` with no session or any token that fails
  `readSubscription` or whose `userId` ≠ the session's user; `400` when the union of topics is
  over `TOPIC_LIMIT` or `tab` is missing; else `200`, headers `content-type: text/event-stream`,
  `cache-control: no-store`, `x-accel-buffering: no`.
- Body: first the catch-up (`hub.changesSince(since, topics)`), then live events, each as
  `id: <id>\ndata: <JSON LiveEvent>\n\n`; a `: ping\n\n` comment every **25 s**. At each ping the
  session is checked again with `findSession` (`src/server/auth/sessions.ts`) and its expiry, without sliding it; gone or expired → the stream
  ends. The client closing the request detaches the stream from the hub.
- `StreamRequest`: `{ tokens: string[]; since: number | null; lastEventId: number | null; tab: string | null }`; `deps`: `{ hub, currentUser, sessionKey, features, now, setInterval }` so tests run without HTTP.
